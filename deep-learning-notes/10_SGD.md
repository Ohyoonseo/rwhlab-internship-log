## 1. SGD 등장 배경: Gradient Descent의 두 가지 문제

| 문제 | 원인 |
|---|---|
| ① 너무 느림 | 매 스텝마다 **모든 데이터**를 다 고려해서 그라디언트 계산 |
| ② 로컬 미니멈에 갇힘 | 항상 같은(가장 신중한) 방향으로만 이동 |

→ 이 두 문제를 **완전히 해결하는 건 아니지만, 어느 정도 완화**해주는 방법이 **SGD**

---

## 2. SGD 핵심 아이디어 (한 문장 요약)

> **랜덤하게 데이터를 하나씩 뽑아서 로스를 만들고, 그 로스로 그라디언트를 구해서 한 스텝 업데이트한다**

### 주머니 비유

- 데이터 5개가 있다면, 각 데이터의 "에러 제곱(오차 제곱)"을 적어서 **주머니에 넣음**
- 주머니를 우르륵 섞어서 **딱 하나만 랜덤하게 뽑음** (예: 1/5 확률로 2번째 데이터가 뽑힘)
- **그 하나의 데이터만으로 만든 로스**를 가지고 그라디언트를 구해서, 한 스텝 이동
- 그 데이터는 다시 주머니에 돌려놓고 → 또 섞어서 → 또 하나 뽑고 → 반복

```
뽑기 → 그라디언트 구하기 → 업데이트 → 주머니에 되돌리기 → 또 뽑기 → ...
```

### 기존 Gradient Descent와 비교

| 구분 | Gradient Descent | SGD |
|---|---|---|
| 매 스텝에서 고려하는 데이터 | 전체 데이터 | 랜덤하게 뽑은 데이터 1개 |
| 신중함 | 매우 신중 (정확한 방향) | 상대적으로 덜 신중 |
| 속도 | 느림 | **빠름** |

- "스토캐스틱(Stochastic)" = 통계적/확률적이라는 의미 → **랜덤하게 뽑는다**는 특징에서 붙은 이름

---

## 3. 반복 학습: 언제까지 계속하는가?

- 한 번 업데이트하고 끝나는 게 아니라, **수렴할 때까지 반복**
- Gradient Descent도 마찬가지로 모든 데이터를 고려한 뒤 한 번 이동하고, 또 모든 데이터를 고려해서 또 이동하는 식으로 반복함
- **수렴 판단 기준**: 그라디언트(미분값)가 충분히 작아지면 → "거의 다 왔다" → 학습 종료
- 반복 학습의 횟수(=**에폭, Epoch**)를 적절히 정해줘야 함

## 4. 왜 SGD의 이동 경로는 삐뚤빼뚤한가? (중요한 통찰)

### 흔히 갖는 의문
- "그라디언트는 항상 가장 가파른 방향을 가리키고, 그 반대 방향으로 가면 최소값으로 향해야 하는데, 왜 SGD 그림은 삐뚤빼뚤 지그재그로 그려질까?"

### 비밀은 등고선에 있다

- 우리가 흔히 보는 **등고선(로스 그래프를 위에서 내려다본 그림)**은 **전체 데이터를 다 고려**해서 그린 등고선임 (예: 5개 데이터를 다 반영한 등고선)
- 하지만 SGD는 **매 스텝마다 데이터를 하나만** 사용함
- **각 데이터 하나하나는 자기 자신만의 로스 함수(자기만의 등고선)를 가지고 있음**
  - 데이터 1개의 등고선 → 자기 자신에 대한 최소값을 향함
  - 데이터 2개의 등고선 → 또 다른 위치의 최소값을 향함
  - (예시로 5개 데이터를 각각 e1², e2², ..., e5²로 표현하면, 각각의 최소점이 서로 다른 위치에 동그라미로 그려짐)

### 결론

> **그라디언트는 틀리지 않았다.** 매 순간 "그 순간 뽑힌 데이터 하나"의 최솟값을 향해 정확히 이동하는 것. 다만 매번 다른 데이터가 뽑히기 때문에, 매 스텝마다 서로 다른 방향(그 데이터만의 최소값 방향)으로 향하게 되어 **전체적으로 봤을 때 지그재그(삐뚤빼뚤)로 보이는 것**

- (전체 데이터의 등고선이 완벽한 원이라고 가정했을 때의 설명이며, 실제로는 타원 등 더 복잡한 형태일 수도 있음)

> 이런 "왜?"를 스스로 파고들어서 이해하는 습관이 중요하다는 이야기(강사의 코멘트) — 기본적인 개념도 깊게 파면 재미있는 통찰이 숨어있음

## 5. 속도 비교: Gradient Descent vs SGD

간단한 예시 계산 (데이터 1개 처리에 1초가 걸린다고 가정):

| 방식 | 계산 방식 | 소요 시간 |
|---|---|---|
| **Gradient Descent** | 한 번 업데이트할 때마다 데이터 5개 전부 고려 (5초) × 4번 업데이트 | 20초 |
| **SGD** | 한 번 업데이트할 때마다 데이터 1개만 고려 (1초) × 8번 업데이트 | 8초 |

- SGD가 업데이트 **횟수**는 더 많아 보여도(8번 vs 4번), 한 번에 걸리는 시간이 훨씬 짧아서 **전체적으로는 훨씬 빠름**
- **데이터가 많아질수록 이 차이는 더 크게 벌어짐**

> 비복원 추출(한 번 뽑은 데이터는 다시 뽑지 않고, 데이터를 다 뽑으면 다시 주머니에 채워 넣고 반복)로 진행하면서 매우 빠르게 이동

---

## 6. SGD의 또 다른 장점: 로컬 미니멈 탈출 가능성

### Gradient Descent의 한계 (복습)
- 항상 가장 가파른 방향으로만 이동 → **가장 가까운 로컬 미니멈에 갇히면 끝**
- 예: 얕은 구덩이(로컬 미니멈)에 빠지면, 근처에 더 깊은 구덩이(글로벌 미니멈)가 있어도 절대 못 감

### SGD는 다르다
- SGD는 매번 다른 데이터를 보기 때문에 **왔다갔다 하며 지그재그로 움직임**
- 이 "흔들림" 덕분에, 얕은 로컬 미니멈에 빠졌다가도 **가끔 그 구덩이를 탈출해서 더 좋은(더 깊은) 곳으로 이동할 가능성**이 생김

### 주의: 절대 보장은 아니다

> **SGD가 무조건 글로벌 미니멈을 찾아준다는 것은 아니다.**

- SGD도 그냥 안 좋은 로컬 미니멈에 갇혀서 끝날 수도 있음
- 다만 Gradient Descent처럼 "가장 가까운 곳에 무조건 갇힌다"는 정도로 심하지는 않고, **탈출의 기회가 조금 더 있다** 정도로 이해하면 됨

## 7. 이번 강의 핵심 요약

- [x] SGD = Gradient Descent의 **느림 + 로컬 미니멈** 문제를 완화하기 위해 등장
- [x] 핵심: **랜덤하게 데이터 1개를 뽑아서** 그 데이터만으로 그라디언트를 구해 업데이트
- [x] "스토캐스틱" = 랜덤하게 뽑는다는 의미
- [x] SGD의 지그재그 경로는 **각 데이터마다 서로 다른 최소값을 향해 정확히 이동**하기 때문에 생기는 자연스러운 현상 (그라디언트 자체는 틀리지 않음)
- [x] 데이터 1개씩 처리하므로 Gradient Descent보다 **훨씬 빠름** (데이터가 많을수록 차이 커짐)
- [x] 지그재그로 움직이는 특성 덕분에 **로컬 미니멈 탈출 기회**가 생길 수 있음 (단, 보장되진 않음)

## 용어 정리

| 용어 | 의미 |
|---|---|
| SGD (Stochastic Gradient Descent) | 데이터를 랜덤하게 1개씩 뽑아 그라디언트를 구하고 업데이트하는 방법 |
| 에폭 (Epoch) | 전체 데이터를 몇 번 반복해서 학습할지를 나타내는 반복 횟수 |
| 비복원 추출 | 한 번 뽑은 데이터는 다시 뽑지 않고, 전체를 다 뽑으면 다시 채워 넣는 방식 |
| 로컬 미니멈 탈출 | SGD의 지그재그 움직임 덕분에 얕은 구덩이에서 벗어날 가능성이 생기는 것 |
