# 11강. 미니배치 SGD (Mini-batch SGD)와 하이퍼파라미터

> 딥러닝 강의 11강 정리 노트

---

## 1. SGD의 문제점: 너무 성급하다

- SGD는 데이터를 **딱 하나씩만** 보고 업데이트함
- 데이터가 100만 개인데 하나씩만 보고 방향을 정하는 건 **너무 성급함** (왔다갔다 심함)
- → 이 문제를 완화하기 위해 등장한 것이 **미니배치(Mini-batch)** 아이디어

---

## 2. 미니배치 SGD란?

> **"하나씩 보는 게 너무 왔다갔다 하면, 둘 이상씩 보자"**

- **미니배치 사이즈(Mini-batch size)**: 한 번에 몇 개의 데이터를 볼지 정하는 값

### 주머니 비유로 이해하기 (미니배치 사이즈 = 2인 경우)

```
1. 주머니에서 데이터 2개를 꺼낸다
2. 두 데이터의 에러를 더해서 로스를 만든다
3. 그 로스로 그라디언트를 구하고 업데이트한다
4. 사용한 데이터를 다시 주머니에 넣는다
5. 반복
```

- 데이터가 5개인데 미니배치 사이즈가 2라면: `2개, 2개, 1개` 순으로 나눠서 처리 (마지막 남는 1개는 그냥 1개로 처리해도 되고, 다시 섞어도 됨 — 선택사항)

### 미니배치 사이즈에 따른 스펙트럼

| 미니배치 사이즈 | 해당 방식 |
|---|---|
| 1 | **SGD** (데이터 1개씩) |
| 전체 데이터 개수와 동일 | **Gradient Descent**와 동일 (모든 데이터를 다 고려) |
| 그 사이의 값 (예: 2, 3, 32, 64...) | **미니배치 SGD** |

> **미니배치 사이즈를 키우면 키울수록, Gradient Descent에 가까워진다**

---

## 3. GPU와 병렬 연산: "느리다"는 문제는 이미 해결됐다?

### CPU vs GPU

- 이전 강의에서 "Gradient Descent는 모든 데이터를 순차적으로 계산해야 해서 느리다"고 설명했는데, 이는 **CPU로 하나씩 순서대로 계산했을 때 이야기**
- **GPU는 병렬 연산이 가능**함
  - 예: 데이터 5개를 각각 1초씩 순차적으로 계산하면 5초가 걸리지만
  - GPU로 **5개를 동시에** 계산하면 **1초**만에 끝남

> **GPU를 쓰면 "Gradient Descent가 느리다"는 문제 자체가 크게 완화됨**

---

## 4. 그런데 왜 배치 사이즈를 무한정 키우지 않을까?

느림 문제가 GPU로 해결됐다면, 배치 사이즈를 무조건 키우면 좋을 것 같지만, 실제로는 그렇지 않음.

### "8K" 논문(ImageNet 관련)의 관찰

- x축: 미니배치 사이즈, y축: 에러(작을수록 좋음)
- **배치 사이즈를 키울수록 에러가 커지는 경향**이 정설로 알려져 있음

### 왜 배치 사이즈가 커지면 성능이 나빠질까?

- 배치 사이즈를 키울수록 → **Gradient Descent에 가까워짐**
- Gradient Descent의 단점(신중하지만 로컬 미니멈에 갇히기 쉬움)을 다시 갖게 됨
  - "느리다"는 단점은 GPU 덕분에 해결됐으니 문제가 안 되지만
  - **로컬 미니멈에 잘 갇히는 성질**은 여전히 남아있어서 성능이 나빠짐

---

## 5. 해결책 (논문에서 제안): 러닝레이트를 같이 키우기 + 웜업(Warm-up)

이 두 가지를 적용하면 배치 사이즈를 키워도 성능 저하를 완화할 수 있다는 제안.

### 제안 ①: 배치 사이즈를 키우면 러닝레이트도 같이 키워라

**직관적 근거: 업데이트 수식 비교**

- MSE는 평균을 사용하므로, 미니배치 크기가 `n`이면 그라디언트에도 자연스럽게 `1/n`이 붙음
- 예: 배치 사이즈 32로 한 번 업데이트하는 것 vs 배치 사이즈 64로 한 번 업데이트하는 것을 비교하면
  - 배치 32는 그라디언트에 `1/32`이 곱해짐
  - 배치 64는 그라디언트에 `1/64`이 곱해짐 (더 많은 데이터를 평균 내므로 그라디언트 크기 자체가 작아지는 경향)
- 배치 64로 한 번 이동한 결과가, 배치 32로 **두 번** 이동한 것과 비슷해지려면 → **러닝레이트를 2배로 키워야** 비슷한 정도로 이동함

> **배치 사이즈를 2배로 키우면, 러닝레이트도 2배로 키워라**

### 제안 ②: 웜업(Warm-up)이 필요한 이유

- 위 "배치 2배 → 러닝레이트 2배" 논리가 성립하려면, **그라디언트가 너무 크게 요동치지 않아야** 함
- 그런데 **학습 초반(웨이트 초기화 직후)**에는:
  - 웨이트가 아직 불안정한 위치에 있어서 **그라디언트가 매우 크고 들쭉날쭉함**
  - 이럴 때 큰 러닝레이트를 그대로 적용하면 학습이 불안정해질 위험이 큼
- → 학습 초반에는 **러닝레이트를 0에서부터 서서히 끌어올리는 "웜업" 과정**이 필요함

### 러닝레이트 스케줄링

- 러닝레이트를 학습 내내 고정(상수)으로 둘 수도 있지만, **상황에 맞게 조절(스케줄링)** 하기도 함
- 다양한 감소 방식이 있음:
  - **코사인 디케이(Cosine Decay)**: 코사인 그래프 형태로 부드럽게 감소
  - **스텝 디케이(Step Decay)**: 계단식으로 뚝뚝 감소
- 어떤 스케줄링 방식을 쓸지는 선택 사항(취사선택)

> 결론: 배치 사이즈를 키울수록 성능이 떨어지는 경향이 있는데, **러닝레이트 조정 + 웜업**을 함께 적용하면 이 문제를 어느 정도 완화할 수 있음 (다만 완벽한 해결은 아니며, 논문에서도 "8K" 정도 배치 사이즈까지는 버텼지만 그 이상은 다시 성능이 나빠지는 경향을 보임)

---

## 6. 용어 정리: 에폭 (Epoch)

> **에폭 = 전체 데이터를 몇 번 반복해서 볼 것인지**

- 주머니 예시로 이해하기:
  - 주머니에서 데이터를 다 꺼내서 한 바퀴 다 쓰면 → **에폭 1 완료**
  - 다시 주머니에 채워 넣고 또 한 바퀴 돌면 → **에폭 2**
  - 이런 식으로 반복

---

## 7. 파라미터 vs 하이퍼파라미터

| 구분 | 정의 | 예시 |
|---|---|---|
| **파라미터 (Parameter)** | **AI가 스스로 알아내는** 값 | 웨이트(Weight), 바이어스(Bias) |
| **하이퍼파라미터 (Hyperparameter)** | **사람이 직접 정해줘야 하는** 값 | 에폭 수, 배치 사이즈, 러닝레이트, 초기 웨이트 방식, 러닝레이트 스케줄링 방식, 모델 구조(레이어 수, 노드 수, 액티베이션 종류), 로스 함수 종류, 최적화 기법(Optimizer) 등 |

### 왜 에폭/배치 사이즈는 파라미터가 될 수 없는가?

- 파라미터는 **그라디언트 디센트(미분)로 학습**되는 값
- 에폭 수, 배치 사이즈는 **정수** 값이고, 애초에 "이걸 편미분한다"는 개념 자체가 성립하지 않음
- → 따라서 이런 값들은 **사람이 직접 정해줘야 하는 하이퍼파라미터**

### 하이퍼파라미터 튜닝

- 실무에서는 다양한 하이퍼파라미터(에폭, 배치 사이즈, 러닝레이트, 모델 구조 등)를 **이리저리 바꿔가며** 가장 좋은 성능을 내는 조합을 찾음
- 모델이 하이퍼파라미터에 너무 민감하게 반응하면 좋은 모델이라 보기 어렵지만, **실제로는 어느 정도 민감한 경우가 많아서** 적절한 하이퍼파라미터 선정 작업이 필요함

---

## 8. 이번 강의 핵심 요약

- [x] **미니배치 SGD**: SGD(1개)와 Gradient Descent(전체) 사이의 절충안 — 여러 개(미니배치 사이즈만큼)의 데이터를 보고 업데이트
- [x] 배치 사이즈를 키울수록 Gradient Descent에 가까워짐
- [x] **GPU의 병렬 연산** 덕분에, 여러 데이터를 동시에 계산할 수 있어서 "느리다"는 문제는 크게 완화됨
- [x] 하지만 배치 사이즈를 키우면 **Gradient Descent의 로컬 미니멈 문제**를 다시 안게 되어 성능이 저하되는 경향이 있음
- [x] 해결책: **배치 사이즈에 비례해서 러닝레이트도 키우고, 학습 초반엔 웜업**을 적용
- [x] **에폭(Epoch)** = 전체 데이터를 몇 번 반복 학습할지
- [x] **파라미터**(AI가 스스로 학습) vs **하이퍼파라미터**(사람이 직접 정해줘야 함) 구분
- [x] 에폭, 배치 사이즈, 러닝레이트, 모델 구조, 로스 함수, 옵티마이저 등은 모두 하이퍼파라미터

---

## 용어 정리

| 용어 | 의미 |
|---|---|
| 미니배치 (Mini-batch) | SGD와 Gradient Descent 사이의 절충 — 여러 개의 데이터를 묶어서 학습 |
| 미니배치 사이즈 (Mini-batch size) | 한 번의 업데이트에 사용하는 데이터 개수 |
| 웜업 (Warm-up) | 학습 초반에 러닝레이트를 0에서부터 서서히 끌어올리는 기법 |
| 코사인 디케이 (Cosine Decay) | 코사인 그래프 형태로 러닝레이트를 부드럽게 감소시키는 스케줄링 |
| 스텝 디케이 (Step Decay) | 계단식으로 러닝레이트를 감소시키는 스케줄링 |
| 에폭 (Epoch) | 전체 데이터를 몇 번 반복해서 학습할지를 나타내는 횟수 |
| 파라미터 (Parameter) | 학습을 통해 AI가 스스로 알아내는 값 (웨이트, 바이어스) |
| 하이퍼파라미터 (Hyperparameter) | 사람이 직접 설정해야 하는 값 (에폭, 배치 사이즈, 러닝레이트 등) |
