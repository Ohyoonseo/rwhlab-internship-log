# 29강. 드랍아웃 (Dropout)

> 딥러닝 강의 29강 정리 노트

---

## 1. 드랍아웃이란?

> **학습 중에 노드를 랜덤하게 일부 탈락(가림)시키면서 훈련시키는 오버피팅 방지 기법**

- 특정 레이어를 골라서 드랍아웃을 적용
- 각 노드에 **"살릴 확률"**을 설정 (예: 0.5)
- 매번 데이터를 통과시킬 때마다, 각 노드가 **동전 던지기하듯** 랜덤하게 살아남거나 탈락함

### 서로 다른 네트워크를 여러 개 학습시키는 셈

- 매 순간 랜덤하게 다른 노드 조합이 살아남기 때문에, 매번 **약간씩 다른 구조의 네트워크**를 학습시키는 것과 같은 효과
- 이렇게 하면 **"일부 노드가 없어도 로스를 잘 줄일 수 있는" 견고한 신경망**을 만들 수 있음

---

## 2. 트레이닝 때 구체적으로 어떻게 동작하는가?

### 배치 사이즈 5인 경우 예시

- 5개의 데이터를 각각 통과시켜 `L1, L2, L3, L4, L5`를 구하고 최종 로스로 합산(MSE 등)
- **중요한 포인트: 데이터 하나(L1)를 통과시킬 때마다, 살릴 노드를 매번 새롭게(랜덤하게) 다시 뽑는다**
  - L1 구할 때: 어떤 노드는 죽고 어떤 노드는 삶
  - L2 구할 때: 또 다시 새롭게 랜덤하게 노드를 뽑음 (L1 때와 다른 조합일 수 있음)
  - ... 이런 식으로 데이터마다 계속 다른 조합으로 훈련
- 이렇게 구한 로스를 미분해서 그라디언트를 얻고, 평소처럼 웨이트를 업데이트

---

## 3. 테스트 때는 완전히 다르게 동작한다 (중요, 헷갈리기 쉬운 부분)

> **트레이닝 때는 일부 노드를 계속 가리지만, 테스트 때는 모든 노드를 다 살린다!**

### 그런데 그냥 다 살리기만 하면 안 되는 이유

- 트레이닝 때는 항상 일부만 살아있는 상태로 학습했는데, 테스트 때 갑자기 전부 다 살리면 **출력값의 스케일 자체가 달라짐** (더 많은 노드의 값이 더해지므로)
- 이를 보정하기 위해, **드랍아웃을 적용한 레이어의 출력값에 "살릴 확률(p)"을 곱해줌**
  - 예: 출력값 × p (활성화 함수를 통과한 결과값에 곱함)
- 이렇게 스케일을 맞춰준 뒤 다음 층으로 전달

### 비유: 회사의 연차 제도

| 상황 | 비유 |
|---|---|
| **트레이닝 때** | 직원들이 번갈아 가며 연차를 씀 — 몇 명이 빠져도 회사(신경망)가 잘 돌아가도록 훈련시킴 |
| **테스트 때** | "대통령이 회사를 방문하는 날"처럼 중요한 날 — 이때는 **전원 출근**해서 최상의 퍼포먼스를 보여줘야 함 |

- 연차 없는 회사(=한 번도 드랍시키지 않고 훈련한 신경망)가 좋은 회사가 아닌 것처럼, 평소에 적절히 일부를 쉬게 하며 훈련하는 것이 전체 조직(신경망)을 더 건강하게 만듦

---

## 4. 왜 드랍아웃이 오버피팅을 막아주는가? — 코어댑테이션(Co-adaptation) 문제

### 문제 상황: 노드가 너무 많으면 생기는 "기계적 암기"

- 노드 수가 필요 이상으로 많으면, 로스는 잘 줄어들긴 하지만
- **각 노드가 의미 있는 특징을 학습하는 게 아니라, 그냥 서로 의존하며 "답을 기계적으로 맞추는 데만" 협력**하게 됨
- 이런 현상을 논문에서는 **코어댑테이션(Co-adaptation)**이라고 부름
  - 노드들이 "상호 의존적으로" 결합해서, 각자 개별적인 의미를 갖기보다는 **집단적으로 답만 맞추는 방식**으로 웨이트가 업데이트됨
  - 결과적으로 데이터를 "이해"하기보다는 "암기"하는 상태 = 오버피팅

### 드랍아웃이 이 문제를 해결하는 방식

> **"내 옆자리 동료가 갑자기 없어도, 회사는 잘 돌아가야 한다"**

- 어떤 노드가 랜덤하게 사라지더라도 로스를 잘 줄여야 하는 상황을 계속 겪다 보면
- 각 노드는 **다른 노드에 의존하지 않고, 스스로 의미 있는 역할을 담당**하도록 성장하게 됨
- 즉, 노드들끼리 서로 "책임을 떠넘기며" 협업하는 게 아니라, **각자가 독립적으로 개성 있는 특징을 뽑아내는 노드로 발전**함

## 5. 실험으로 확인하기: 오토인코더(Autoencoder)를 이용한 시각화

### 오토인코더란?

> **입력된 이미지가 그대로 다시 출력되도록(자기 자신을 복원하도록) 학습시키는 구조**

```
구조: 입력(28×28=784 픽셀) → 인코더(256 노드로 압축) → 디코더(다시 784 노드로 복원) → 출력
```

- **인코더(Encoder)**: 입력을 압축하는 부분
- **디코더(Decoder)**: 압축된 것을 다시 복원하는 부분
- 핵심: **인코더가 압축을 잘해야, 디코더가 복원을 잘할 수 있음** (마치 파일을 압축(zip)했다가 풀었을 때 원본이 손실 없이 나와야 하는 것과 같은 원리)

### 실험 결과: 재구성된 이미지 품질

- 드랍아웃 미적용 vs 적용 비교 시, 드랍아웃을 적용한 쪽이 오히려 약간 더 뿌옇게 나옴 (실험상 관찰된 결과 — 원 논문에서는 성능이 비슷하다고 보고됨)

### 진짜 흥미로운 부분: 각 노드가 학습한 "웨이트 맵" 시각화

- 인코더의 256개 노드 각각이 가진 웨이트를 **28×28 이미지 형태(웨이트 맵)**로 시각화
  - 각 노드의 웨이트를 이미지처럼 펼쳐보면, "이 노드가 입력 이미지의 어느 부분을 중요하게 보는지"를 시각적으로 확인 가능

### 비교 결과

| 구분 | 웨이트 맵의 특징 |
|---|---|
| **드랍아웃 미적용** | 노드들의 웨이트 맵이 서로 **비슷비슷하고 특색이 없음** (코어댑테이션 현상) |
| **드랍아웃 적용** | (학습에 실패해 자글거리는 일부 노드를 제외하면) 각 노드가 **이미지의 서로 다른 특정 부분(획, 패턴 등)을 집중해서 담당**하는 모습이 뚜렷하게 나타남 |

> **결론: 드랍아웃을 적용하면 각 노드가 "이 부분에 획이 있는지 없는지", "이런 패턴이 있는지" 등 각자 의미 있는 특징을 담당하도록 역할 분담이 잘 이루어진다**

- 이는 드랍아웃이 단순히 "성능 수치"만 개선하는 게 아니라, **신경망 내부의 노드들이 실제로 더 의미 있고 해석 가능한 특징을 학습하도록 유도**한다는 것을 시각적으로 보여주는 실험

## 6. 이번 강의 핵심 요약

- [x] **드랍아웃**: 학습 중 노드를 랜덤하게 탈락시켜, 마치 여러 개의 서로 다른 네트워크를 학습시키는 효과를 내는 오버피팅 방지 기법
- [x] 트레이닝 때는 데이터(또는 배치 내 각 데이터)마다 매번 새롭게 랜덤한 노드 조합으로 학습
- [x] **테스트 때는 모든 노드를 살리되, 출력값에 "살릴 확률(p)"을 곱해서 스케일을 보정**함 (트레이닝/테스트가 다르게 동작하는 중요한 포인트)
- [x] 오버피팅의 원인 중 하나인 **코어댑테이션(Co-adaptation)** — 노드가 너무 많으면 서로 의존하며 기계적으로 답만 맞추게 되는 현상
- [x] 드랍아웃은 "일부 노드가 없어도 학습이 되어야 하는" 상황을 반복시켜, **각 노드가 독립적으로 의미 있는 특징을 학습**하도록 유도
- [x] 오토인코더 실험에서, 드랍아웃 적용 시 각 노드의 웨이트 맵이 **서로 다른 특정 부분에 집중하는 개성 있는 패턴**을 보이는 것을 시각적으로 확인함 (미적용 시에는 노드들이 서로 비슷비슷했음)

---

## 용어 정리

| 용어 | 의미 |
|---|---|
| 드랍아웃 (Dropout) | 학습 중 노드를 랜덤하게 탈락시켜 오버피팅을 방지하는 기법 |
| 코어댑테이션 (Co-adaptation) | 노드들이 서로 의존하며 기계적으로 정답만 맞추게 되는, 오버피팅과 관련된 현상 |
| 오토인코더 (Autoencoder) | 입력을 압축(인코딩)했다가 다시 복원(디코딩)하도록 학습시키는 신경망 구조 |
| 웨이트 맵 (Weight Map) | 노드의 웨이트를 이미지 형태로 시각화한 것 — 그 노드가 어떤 부분을 중요하게 보는지 확인 가능 |
