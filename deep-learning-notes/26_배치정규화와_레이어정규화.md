# 26강. 배치 정규화(Batch Normalization)와 레이어 정규화

> 딥러닝 강의 26강 정리 노트

---

## 1. 문제 상황: 들 값이 한쪽으로 치우치면 비선형성을 잃는다

### 배치 사이즈 5로 예시 설정

- 특정 노드에 배치 사이즈 5만큼의 데이터가 통과하면, 그 노드의 "들 값(pre-activation)"이 **5개** 생김
- 이 5개의 들 값이 어떻게 분포되어 있는지가 중요함

### 극단적인 경우 ①: 5개 값이 전부 양수라면?

- ReLU(또는 시그모이드의 특정 구간)를 사용한다고 했을 때, 값이 전부 양수 영역에만 있으면
- 그 구간에서 활성화 함수가 사실상 **Linear Activation처럼 동작**해버림 (ReLU는 양수 구간에서 `y=x`와 동일)
- → 베니싱 그라디언트는 해결되지만(미분값이 1), **비선형성(Non-linearity)을 전혀 확보하지 못함**

### 극단적인 경우 ②: 5개 값이 전부 음수라면?

- ReLU 기준: 음수 구간은 전부 0 → 미분도 0, 값도 다 0으로 죽어버림 → **완전히 망한 상태**

### 시그모이드의 경우도 비슷한 딜레마

- 시그모이드 그래프를 보면:
  - **가운데(0 근처)**: 미분이 크고(최대 1/4) 비선형성이 잘 드러나는 구간
  - **양 끝(매우 크거나 작은 값)**: 그래프가 거의 평평(누워있음) → 미분도 작고, 게다가 거의 **선형(Linear)에 가까움** → 비선형성도 확보 못함

> **결론: 들 값이 적절한 위치(대략 중간쯤)에 분포해야, 미분도 살아있고 비선형성도 잘 확보된다**

## 2. 해결 아이디어: 들 값을 "재배치"하자 — 배치 정규화(Batch Normalization)

### 핵심 컨셉

> **여러 데이터에서 나온 들 값들의 "순서는 유지"하되, 전체적으로 어디에(평균) 얼마나 퍼지게(분산) 재배치할지를 조정하자**

- 비유: 모래알 다섯 개를 뿌린다고 할 때
  - **어디에 뿌릴지** = 평균(mean) 조정
  - **얼마나 세게 뿌릴지(퍼지는 정도)** = 분산(variance) 조정

### 그런데 "어디로" 재배치해야 좋을지는 사람이 정하기 어렵다

- 단순히 "평균 0, 분산 1로 맞추면 되지 않을까?"라고 생각하기 쉽지만
- 활성화 함수마다 "적절한 구간"이 다르기 때문에, 일률적으로 정하기 어려움

### 배치 정규화의 진짜 대단한 점: "어디로 재배치할지도 학습시켜버린다"

> **재배치할 위치(평균)와 퍼짐 정도(분산)를 사람이 정하는 게 아니라, AI가 그라디언트 디센트로 직접 학습하게 만든다**

---

## 3. 배치 정규화의 계산 과정

### 1단계: 정규화 (Normalization) — 고등학교 수준의 기본 통계

```
평균을 뺀다 → 표준편차로 나눈다
```

- 예: 값이 `1,2,3,4,5`라면
  - 평균 = 3
  - 평균을 빼면 → `-2,-1,0,1,2` (평균 = 0)
  - 표준편차로 나누면 → 평균은 여전히 0(변하지 않음), **분산은 정확히 1**이 됨

### 2단계: 학습 가능한 파라미터 a, b로 재배치

```
출력 = a × (정규화된 값) + b
```

- 이 결과의 **평균은 b**, **분산은 a²**가 됨
- 즉, `a`와 `b`를 조절하면 원하는 어디로든(어떤 평균으로), 얼마나 퍼지게든(어떤 분산으로) 값을 재배치할 수 있음

### a, b는 어떻게 학습되는가?

- `a`로 편미분하면 값이 나오고, `b`로 편미분해도 값이 나옴 (모두 미분 가능)
- → **웨이트, 바이어스와 완전히 동일한 방식으로, 그라디언트 디센트를 통해 학습되는 새로운 파라미터**
- 학습 목표는 동일: **로스를 최소화하는 방향으로 a, b가 스스로 조정됨**

> **결국 "얼마나 비선형성을 살리고, 얼마나 베니싱 그라디언트를 해결할지"의 트레이드오프를, 사람이 정하는 게 아니라 AI가 스스로 알아내게 만든 것 — 이것이 배치 정규화가 대박인 이유**

### 적용 위치

- 보통 **활성화 함수(액티베이션) 통과 직전**에 적용 (활성화 함수 후에 적용하는 경우도 있지만 일반적으로는 전에 함)
- **각 노드마다** 독립적으로 `a`, `b` 한 쌍씩 존재 (노드가 3개면 `a1,b1 / a2,b2 / a3,b3`로 총 6개의 새 파라미터 추가)

## 4. 트레이닝 때와 테스트 때, 다르게 동작해야 하는 이유

### 문제: 테스트 때는 데이터 하나만 들어올 수도 있음

- 배치 정규화는 **배치 단위로 평균/분산**을 구하는 방식
- 테스트 시점에 데이터를 하나씩만 넣는다면? → 평균은 그 값 자신, **분산은 0**이 되어버려 정상적으로 계산이 안 됨

### 해결책: 트레이닝 때 구한 평균/분산을 무빙 에버리지로 저장해두기

- 학습 중에 매 배치마다 구해지는 평균(`x̄`)과 표준편차(`σ`)를 **지수 이동평균(Moving Average)** 방식으로 계속 누적 저장
  - Adam에서 m, v를 무빙 에버리지로 관리했던 것과 같은 원리
- **테스트 시점에는 그때그때 새로 구하지 않고, 학습 때 저장해둔 이 무빙 에버리지 값을 그대로 사용**

---

## 5. 배치 정규화의 단점: 배치 사이즈에 민감함

- 배치 사이즈가 작으면(예: 2개), 그 2개 데이터만으로 구한 평균/분산이 **매번 크게 요동칠 수 있음**
- 어떤 2개가 뽑히느냐에 따라 평균/분산이 들쭉날쭉해지고, "어디로 재배치할지"를 안정적으로 학습하기 어려워짐
- **→ 배치 사이즈가 충분히 커야 배치 정규화가 안정적으로 잘 작동함**

---

## 6. 실험 결과: 배치 정규화의 위력 확인

### 실험 설정

- 손글씨 숫자(0~9) 분류 문제, 시그모이드 활성화 함수 사용 (**활성화 함수 자체는 바꾸지 않음**)
- 배치 정규화 적용 전 vs 적용 후 비교

### 결과

| 구분 | 결과 |
|---|---|
| 배치 정규화 적용 전 | 최종 정확도 **10%** (완전히 랜덤 찍기 수준, 학습이 전혀 안 됨) |
| 배치 정규화 적용 후 | 최종 정확도 **94.4%** |

> **활성화 함수는 그대로 시그모이드인데, 배치 정규화 하나만 추가했을 뿐인데도 이렇게 극적인 차이가 발생함**

### 마지막 레이어의 들 값 변화 관찰 (영상으로 확인한 내용)

- **배치 정규화 미적용**: 처음엔 그나마 괜찮은 위치(0 근처)에서 시작하지만, 학습이 진행되며 그라디언트가 시키는 대로 값이 점점 한쪽(왼쪽)으로 쏠려버림 → 그 지점은 시그모이드가 거의 평평한 구간이라 미분이 완전히 0에 가까워짐 → 베니싱 그라디언트 심화 → 이후 업데이트가 거의 멈춤
- **배치 정규화 적용**: 처음엔 비슷하게 왼쪽으로 쏠리려는 경향을 보이다가도, **"그쪽으로 가면 그라디언트가 사라진다"는 것을 학습을 통해 스스로 깨닫고, 다시 중간(적절한 위치)으로 값을 끌고 옴**
- 이 덕분에 첫 번째 레이어까지도 값이 계속 의미 있게 움직이며 학습이 이루어짐

## 7. 참고: 레이어 정규화 (Layer Normalization)

### 핵심 차이: 평균·분산을 "어떤 축"으로 구하느냐

| 방식 | 평균·분산을 구하는 기준(축) |
|---|---|
| **배치 정규화 (Batch Norm)** | **배치(batch) 축** — 같은 노드에서, 여러 데이터(배치)에 걸쳐 나온 값들로 평균/분산 계산 |
| **레이어 정규화 (Layer Norm)** | **레이어(layer) 축** — 하나의 데이터에서, 같은 층에 있는 여러 노드의 값들로 평균/분산 계산 |

- 예: 노드가 3개인 층이 있다면
  - 배치 정규화: (같은 노드에서) 배치 사이즈만큼의 값들을 모아서 평균/분산
  - 레이어 정규화: (같은 데이터에서) 그 층의 3개 노드 값을 모아서 평균/분산

- 학습 파라미터(a, b)는 두 방식 모두 노드당 한 쌍씩 존재 (구조는 동일, 계산 축만 다름)

### 레이어 정규화의 장점

- **배치 사이즈에 영향을 받지 않음** — 하나의 데이터 안에서 자체적으로 평균/분산을 구하기 때문
- 트레이닝 때와 테스트 때 **동일한 방식으로 계산 가능** (무빙 에버리지를 따로 저장할 필요 없음) — 매 데이터마다 그 자리에서 바로 평균/분산을 구할 수 있기 때문

### 왜 자연어 처리에서는 레이어 정규화를 주로 쓰는가?

- 자연어 데이터는 문장 길이가 서로 다르기 때문에, 짧은 문장은 **패드 토큰(Pad Token)**으로 채워서 길이를 맞춤
- 배치 정규화처럼 배치 축(여러 문장에 걸쳐)으로 평균/분산을 구하면, 문장 끝부분에는 대부분 패드 토큰만 있어서 **통계치가 왜곡됨**
- 레이어 정규화는 (문장 하나 내에서) 임베딩 차원 축으로 평균/분산을 구하기 때문에 이런 문제가 없음 → **자연어 처리(NLP)에서는 레이어 정규화가 더 적합**

### 이미지 데이터의 정규화 방식들 (참고)

- 이미지 데이터에서는 배치 정규화, 레이어 정규화 외에도 **인스턴스 정규화, 그룹 정규화** 등 다양한 변형이 있음
- 각각 "행/열/채널/배치" 중 어떤 축들을 묶어서 평균/분산을 구하느냐에 차이가 있음
- (일부 논문, 예: ConvNeXt 등에서는 레이어 정규화를 픽셀 단위로 세밀하게 적용하는 경우도 있음 — 어느 정도 구현상의 자유도가 있는 부분)

## 8. 베니싱 그라디언트 해결책 총정리

> **레이어를 깊게 쌓으면서도 베니싱 그라디언트를 막고 비선형성을 유지하기 위한 대표적인 두 가지 방법**

1. **활성화 함수를 ReLU(또는 그 변형)로 바꾼다**
2. **배치 정규화 또는 레이어 정규화를 사용한다**

- 두 방법 모두 "비선형성을 살리면서 베니싱 그라디언트도 해결"하려는 공통된 목표를 가짐

## 10. 이번 강의 핵심 요약

- [x] 들 값이 활성화 함수의 한쪽 극단(전부 양수 또는 전부 음수, 혹은 그래프가 평평한 구간)에 몰리면 **미분이 죽거나 비선형성을 잃는 문제**가 생김
- [x] **배치 정규화(Batch Normalization)**: 정규화(평균 0, 분산 1)를 먼저 하고, 학습 가능한 파라미터 `a`(분산 조절), `b`(평균 조절)로 값을 다시 재배치
- [x] `a`, `b`는 웨이트·바이어스와 똑같이 **그라디언트 디센트로 학습**되며, "어디에 재배치해야 로스가 최소화되는지"를 AI가 스스로 알아냄
- [x] 트레이닝 때는 배치별 평균/분산을 사용하지만, **테스트 때는 학습 중 저장해둔 무빙 에버리지 값을 사용**
- [x] 배치 정규화는 **배치 사이즈가 작으면 불안정**해지는 단점이 있음
- [x] 실험 결과: 시그모이드를 그대로 쓰고 배치 정규화만 추가해도 정확도가 10% → 94.4%로 극적으로 향상
- [x] **레이어 정규화**: 배치 축이 아니라 **레이어(같은 데이터의 노드들) 축**으로 평균/분산을 구함 — 배치 사이즈에 영향받지 않고, 트레인/테스트 시 동일하게 계산 가능
- [x] 자연어 처리에서는 **패드 토큰으로 인한 통계 왜곡 문제** 때문에 배치 정규화보다 레이어 정규화가 더 적합
- [x] 베니싱 그라디언트 해결책 정리: **① ReLU 계열 활성화 함수, ② 배치/레이어 정규화**

---

## 용어 정리

| 용어 | 의미 |
|---|---|
| 배치 정규화 (Batch Normalization) | 배치 축으로 평균/분산을 구해 정규화하고, 학습 가능한 파라미터로 재배치하는 기법 |
| 레이어 정규화 (Layer Normalization) | 레이어(같은 데이터 내 노드들) 축으로 평균/분산을 구해 정규화하는 기법 |
| 패드 토큰 (Pad Token) | 문장 길이를 맞추기 위해 짧은 문장 뒤에 채워 넣는 더미 토큰 |
| 무빙 에버리지 (Moving Average) | 배치 정규화에서 트레이닝 중 평균/분산을 지수적으로 누적해, 테스트 시 사용하기 위해 저장하는 방식 |
