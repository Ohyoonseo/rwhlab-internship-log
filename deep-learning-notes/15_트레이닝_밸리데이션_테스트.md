# 15강. 트레이닝 / 밸리데이션 / 테스트 데이터

> 딥러닝 강의 15강 정리 노트

---

## 1. 트레이닝(Training)과 테스트(Test) 복습

| 구분 | 역할 |
|---|---|
| **트레이닝 데이터** | 정답을 알려주며 학습시키는 데이터 ("이건 강아지야", "이건 고양이야") |
| **테스트 데이터** | 학습이 끝난 후, **처음 보는** 데이터로 잘 맞히는지 확인하는 데이터 |

### 핵심 원칙: 테스트 데이터는 절대 학습 과정에 관여하면 안 된다

> **테스트 데이터의 정의 자체가 "처음 보는 데이터"** — 학습에 사용해버리면 더 이상 "처음 보는 데이터"가 아니게 됨

- 이건 단순히 "도덕적으로 문제"인 게 아니라, **모델의 성능 자체에도 안 좋은 영향**을 줌
- **AI의 진짜 목표는 트레이닝 데이터를 잘 맞히는 게 아니라, 테스트 데이터(=실전)에서 잘하는 것**

---

## 2. 문제 상황: 트레이닝 데이터만으로는 "언제 학습을 멈춰야 할지" 알기 어렵다

### 에폭(Epoch)에 따른 로스 변화 그래프

- **트레인 로스(Train Loss)**: 에폭이 늘어날수록 계속 (조금씩이라도) 줄어드는 경향을 보임
- 하지만 트레인 로스만 보고는 "어느 시점에서 멈추는 게 최선인지" 판단하기 어려움

### 테스트 로스(Test Loss)를 함께 그려보면?

- 트레인 로스는 계속 감소하는데, **테스트 로스는 어느 시점 이후로 오히려 다시 증가**하는 패턴이 나타남
- 이 현상이 바로 **오버피팅(Overfitting)** (자세한 내용은 이후 강의에서 다룰 예정)

### 오버피팅의 의미: "답을 외워버렸다"

- 조회수-수익 예측 예시로 생각해보면:
  - 학습을 너무 많이 시키면, 로스를 완전히 0으로 만들기 위해 **가진 데이터 하나하나에 억지로 딱 맞춰서** 구불구불한 곡선을 만들어버림
  - 그 결과, **가진 데이터에는 완벽히 맞지만, 처음 보는(테스트) 데이터에는 오히려 예측이 부정확**해짐
- 즉, 학습을 무조건 오래 시킨다고 좋은 게 아니라, **적절한 시점에 멈추는 것이 중요**

---

## 3. 그렇다고 "테스트 로스가 가장 낮을 때 멈추자"도 안 되는 이유

### 얼핏 보면 합리적인 생각

> "테스트 로스도 그릴 수 있으니, 테스트 로스가 최소가 되는 에폭에서 멈추면 되지 않을까?"

### 하지만 이것도 문제 (일종의 치팅)

> **테스트 로스를 기준으로 에폭(하이퍼파라미터)을 정하는 것은 그 자체로 "치팅"이다**

- 이렇게 하면 결국 **내가 가진 테스트 데이터에 대해서만 최적화**하게 되는 셈
- 진짜 목표는 "무한히 많은, 아직 보지 못한 데이터"에 대해서도 잘하는 것인데
- 테스트 로스를 기준으로 에폭을 정해버리면, **그 특정 테스트 데이터셋에만 맞춰진 모델**이 되어버림
- 만약 테스트 데이터가 무한하다면 문제없겠지만, 실제로는 **유한한 데이터셋**이기 때문에 이 방식은 "모든 상황을 대변하지 못함"

> 여기서 "치팅"이라고 부르는 이유는 도의적 문제가 아니라, **진짜 좋은 모델을 만들 수 없기 때문**

---

## 4. 해결책: 밸리데이션(Validation) 데이터

### 밸리데이션 데이터란?

> **트레이닝 데이터의 일부를 따로 떼어내서, 테스트 데이터처럼 사용하는 것**

- 그라디언트를 구하는 데(직접적인 학습에)는 **참여시키지 않음**
- 마치 "가짜 테스트 데이터"처럼 사용해서, 학습 과정 중간중간 모델의 성능을 체크하는 용도

### 밸리데이션 데이터의 역할

- **에폭 같은 하이퍼파라미터를 정할 때는, 반드시 밸리데이션 데이터를 기준으로 삼아야 함**
- 테스트 로스처럼 밸리데이션 로스도 계속 감소하지는 않음 (학습에 직접 참여하지 않으므로 당연함)
- **간접적으로는 관여**함 — 하이퍼파라미터(에폭 수 등)를 정할 때 그 기준이 되기 때문

### 왜 밸리데이션 데이터를 쓰는 게 그나마 나은 방법인가?

- 이렇게 해도 결국 "밸리데이션 데이터에 피팅되는 것 아니냐"는 지적은 가능함 → **맞음, 어쩔 수 없는 부분**
- 하지만 **진짜 테스트 데이터는 학습 과정에서 단 한 번도 사용되지 않기 때문에**, 최종적으로 "진짜 처음 보는 데이터"에 대한 성능을 공정하게 확인할 수 있음

### 실제 사례: 캐글(Kaggle) 대회

- 대회 참가자에게 주어지는 데이터와 별개로, **진짜 최종 테스트 데이터는 따로 숨겨놓음**
- 대회가 끝난 후에야 이 숨겨진 테스트 데이터로 **최종 순위**를 매김
- 이런 방식을 통해 공정성을 확보함

## 5. 세 종류 데이터 역할 정리 (수능 비유)

| 데이터 종류 | 역할 | 비유 |
|---|---|---|
| **트레이닝 데이터** | 파라미터(웨이트, 바이어스)를 학습시키기 위한 데이터 | **연습 문제** |
| **밸리데이션 데이터** | 하이퍼파라미터(에폭, 모델 구조 등)를 선택하기 위한 데이터 | **모의고사** |
| **테스트 데이터** | 최종적으로 학습된 모델의 성능을 평가하는 데이터 | **수능(실전)** |

> 모의고사(밸리데이션)를 보고 "아, 국어가 약하네, 공부법을 이렇게 바꿔야겠다"처럼 부족한 부분을 파악해서 조정하는 것과 같은 원리 — 사람의 학습 방식과 유사함

---

## 6. 밸리데이션 데이터로 "모델 자체"를 선택하는 예시

하이퍼파라미터는 에폭 수만이 아니라 **모델 구조(레이어 개수, 노드 개수 등)**도 포함됨. 밸리데이션 데이터로 어떤 모델이 더 나은지도 판단할 수 있음.

### 예시: 모델 1(단순한 구조) vs 모델 2(복잡한 구조)

- 두 모델 각각에 대해 에폭별 트레인 로스 / 밸리데이션 로스 그래프를 그려봄
- **모델 2**: 구조가 복잡해서 트레이닝 로스는 매우 낮게(거의 0에 가깝게) 떨어짐
- **모델 1**: 구조가 단순해서 트레이닝 로스는 모델 2보다 덜 낮아짐

### 그런데 밸리데이션 로스로 비교해보면?

- 모델 1의 최소 밸리데이션 로스(`벨1`)가, 모델 2의 최소 밸리데이션 로스(`벨2`)보다 **더 작음**
- → **트레이닝 로스는 모델 2가 훨씬 낮지만, 실제로 선택해야 할 모델은 밸리데이션 로스가 더 낮은 모델 1**

> **트레이닝 로스가 낮다고 좋은 모델이 아니다** — 트레이닝 로스가 아무리 낮아도, 밸리데이션 로스가 높다면 그건 오버피팅된(답을 외운) 모델일 뿐

### 결론

> **모델 구조 선택도 하이퍼파라미터 선택의 일종이며, 반드시 밸리데이션 로스를 기준으로 판단해야 한다**

## 7. 이번 강의 핵심 요약

- [x] **테스트 데이터는 학습 과정에 절대 관여하면 안 됨** — "처음 보는 데이터"라는 정의 자체가 깨지기 때문
- [x] 트레인 로스는 계속 줄지만, 테스트 로스는 어느 순간부터 다시 증가 (오버피팅)
- [x] **테스트 로스를 기준으로 에폭 등을 정하는 것도 일종의 치팅** — 그 특정 테스트셋에만 맞춰진 모델이 되어버림
- [x] 해결책: **밸리데이션 데이터** — 트레이닝 데이터 일부를 떼어내서, 학습(그라디언트 계산)에는 참여시키지 않고 테스트처럼 활용
- [x] 하이퍼파라미터(에폭 수, 모델 구조 등)는 반드시 **밸리데이션 로스**를 기준으로 선택
- [x] 트레이닝(연습 문제) / 밸리데이션(모의고사) / 테스트(수능) 비유로 세 데이터의 역할을 구분
- [x] 트레이닝 로스가 낮다고 좋은 모델이 아니며, **밸리데이션 로스가 낮은 모델을 선택**해야 함
- [x] 캐글 등 실제 대회에서는 진짜 테스트 데이터를 대회 종료 후에만 공개해서 공정성을 확보

## 용어 정리

| 용어 | 의미 |
|---|---|
| 트레이닝 데이터 (Training Data) | 웨이트·바이어스(파라미터)를 학습시키는 데 사용하는 데이터 |
| 테스트 데이터 (Test Data) | 최종 모델 성능을 평가하는, 학습에 전혀 관여하지 않는 데이터 |
| 밸리데이션 데이터 (Validation Data) | 트레이닝 데이터 일부를 떼어내어 하이퍼파라미터 선택에 사용하는 데이터 |
| 오버피팅 (Overfitting) | 트레이닝 데이터에는 지나치게 잘 맞지만, 새로운 데이터에는 성능이 떨어지는 현상 |
| 치팅 (Cheating, 데이터 유출) | 테스트/밸리데이션 데이터를 학습 결정 과정에 부적절하게 사용하는 것 |
