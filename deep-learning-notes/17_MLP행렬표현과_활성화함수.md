## 1. MLP를 행렬과 벡터로 표현하기

### 왜 행렬로 표현할까?

- 지금까지는 `x1×w1 + x2×w2 + b1` 처럼 하나하나 풀어서 표현했음
- 하지만 노드 개수가 많아지면(예: 100개) 이런 표현은 너무 복잡해짐
- **행렬과 벡터로 표현하면 노드 수와 상관없이 항상 간결하게 표현 가능** → 대부분의 논문이 이 표기법 사용

### 예시: 입력 2개 → 은닉 3개 → 출력 2개인 MLP

**1층 (입력 2개 → 은닉 3개)**

```
입력: x = [x1, x2]  (1×2 행 벡터)
웨이트 행렬: W1 (2×3)   ← 입력 2개, 출력 3개이므로 2×3
바이어스: b1 = [b1, b2, b3]  (1×3)

들 값(pre-activation) = x·W1 + b1   → 결과: 1×3
활성화 함수 통과: F1(x·W1 + b1)      → 결과: 1×3
```

- 행렬 곱셈의 규칙: **안쪽 숫자(x의 열 수와 W1의 행 수)가 일치해야 함** → `1×2` 와 `2×3`을 곱하면 `1×3` 결과
- `W1`의 각 **열**이 은닉층의 각 노드에 대응되는 웨이트들을 담고 있음

**2층 (은닉 3개 → 출력 2개)**

```
웨이트 행렬: W2 (3×2)   ← 입력 3개, 출력 2개이므로 3×2
바이어스: b2 = [b1, b2]  (1×2)

출력 = F2( [F1(x·W1+b1)] · W2 + b2 )   → 결과: 1×2
```

### 전체 수식 정리

```
h = F1(x·W1 + b1)     ← 1층 통과
y = F2(h·W2 + b2)     ← 2층 통과
```

> **인공신경망 = "행렬 곱하고, 벡터 더하고, 액티베이션 통과"를 반복하는 것**

- 이 표현 방식 덕분에 노드가 아무리 많아져도(예: 100개), 수식 자체는 간결하게 유지됨 — 그때그때 행렬/벡터의 **shape(크기)**만 알면 됨
- 이 수식을 보고 거꾸로 **신경망 구조도를 그릴 수도 있음** (수식 ↔ 그림이 서로 대응됨)
- 다시 한번 확인: **인공신경망 = 함수** (입력 x가 들어가서 일련의 연산을 거쳐 출력 y가 나오는 함수)

## 2. 핵심 질문: 층을 깊게 쌓으면 무조건 더 복잡한 함수를 표현할 수 있을까?

> **정답: 아니다! 활성화 함수(Activation)에 따라 다르다**

### Linear Activation만 쓰면 아무리 깊어도 소용없다

**증명: 2개 층을 모두 Linear Activation으로 만들어서 전개해보기**

```
h = x·W1 + b1        (F1이 Linear이므로 그대로 통과)
y = h·W2 + b2         (F2도 Linear이므로 그대로 통과)

y = (x·W1 + b1)·W2 + b2
  = x·W1·W2 + b1·W2 + b2       (분배법칙)
  = x·(W1·W2) + (b1·W2 + b2)
```

- `W1·W2`는 그냥 **하나의 행렬**로 치환 가능 (`W1`이 2×3, `W2`가 3×2 → 곱하면 2×2인 하나의 행렬)
- `b1·W2 + b2`도 그냥 **하나의 벡터**로 치환 가능

```
y = x·W + b   (W, b는 새로 치환된 하나의 행렬/벡터)
```

> **결론: 2개 층을 Linear Activation으로 쌓아도, 결국 "1개 층짜리" 구조와 완전히 동일한 표현력밖에 갖지 못한다**

### 직관적으로 이해하기: 선형회귀의 예시

> **문제: `y = (a1×a2)x + b` (파라미터 3개, a1·a2를 각각 학습) vs `y = ax + b` (파라미터 2개, a 하나만 학습) — 완벽히 학습됐을 때 성능 차이가 있을까?**

- **정답: 성능은 완전히 동일하다**
- `a1`과 `a2`는 그냥 곱해져서 하나의 기울기 역할만 할 뿐 — 굳이 둘로 쪼개서 학습시키나, 하나로 합쳐서 학습시키나 결과는 같음
- 마찬가지로 `W1·W2`도 두 개로 쪼개봐야 그냥 곱해서 하나의 행렬이 될 뿐 → **가운데 층이 사실상 무시되고, 고속도로처럼 그냥 통과되어 버림**

### 여러 층을 Linear로 쌓아도 결과는 같음 (예: Linear-Linear-Linear)

- 층을 3개, 4개로 더 늘려서 전개해봐도, 결국 계속 "행렬 곱하기 행렬"이 반복될 뿐이라 **결국 하나의 행렬로 합쳐짐**
- 즉, **Linear Activation만 계속 쓴다면, 몇 층을 쌓든 표현력은 딱 1층(Fully Connected 1개)짜리에 머무름**

---

## 3. 그래서 Non-linear(비선형) Activation이 중요하다

> **비선형 활성화 함수를 사용해야만, 층을 깊게 쌓는 것이 실제로 더 복잡한 함수를 표현하는 데 의미가 있다**

- Linear만 쓴 신경망: 입력과 출력 간의 **선형적인 관계**만 표현 가능 (스칼라로 생각하면 그냥 `ax+b`, 즉 직선)
- **비선형 활성화 함수(Non-linear Activation)**를 쓰면:
  - 입력과 출력 간의 **비선형적인 관계**도 표현 가능
  - **층을 깊게 쌓을수록 점점 더 복잡한 함수**를 표현할 수 있게 됨

### 참고: Linear - Non-linear - Linear - Non-linear... 처럼 섞어 쓰는 경우

- 이런 구조를 전개해봐도, **Linear로만 연결된 부분들은 서로 합쳐져서 하나의 층처럼 취급됨**
- 결과적으로 **"비선형 활성화 함수가 몇 번 등장하는지"에 따라 실질적인 표현력(층 수)이 결정됨**
  - 예: Linear-Nonlinear-Linear-Nonlinear 구조는 실질적으로 **2개 층짜리 표현력**을 가짐 (비선형이 2번 등장)

---

## 4. 그렇다면 Linear Activation은 쓸모없는가? — 아니다, 쓰이는 곳이 있다

### 사용 사례 ①: 회귀(Regression) 문제의 마지막 출력층

- 회귀 문제는 출력값이 **마이너스 무한대부터 플러스 무한대까지** 나올 수 있어야 함
- 그래서 마지막 층에는 값을 제한하지 않는 **Linear Activation을 사용**하는 것이 관례

**반박 가능성 검토: "비선형이면서 -∞~∞ 범위도 되는 함수는 없을까?"**
- 예: `x³` 같은 함수도 -∞~∞ 범위를 가지면서 비선형성도 가짐
- 하지만 굳이 이런 특이한 함수를 마지막 층에 쓸 필요는 없음
  - 비선형성이 부족하다고 느껴진다면, **차라리 층을 하나 더 늘리는 게 나음**
  - 예: 100층짜리 비선형 함수가 필요하다면, "99층은 ReLU + 마지막 1층은 Linear"로 구성하면 됨
  - 굳이 마지막 층에서 무리하게 특이한 활성화 함수(`x³` 등)를 써서 리스크를 감수할 필요가 없음 (그라디언트 계산 등에 안 좋은 영향을 줄 수도 있음)

### 사용 사례 ②: 정보 손실 방지 (예: MobileNetV2 논문)

- 신경망 구조에서 노드 수가 **줄어들었다가 다시 늘어나는** 구간이 있는 경우 (예: 5개 → 2개 → 5개)
- 이렇게 **축소되는 층**에서 ReLU 같은 활성화 함수를 쓰면:
  - ReLU는 **음수를 전부 0으로 만들어버림** → 정보의 절반 가까이가 손실될 위험
  - 노드 수가 이미 줄어든 좁은 구간에서 추가로 정보까지 잃으면 손실이 더 커짐
- → 이런 **축소된(bottleneck) 층에서는 비선형성을 일부 포기하더라도, Linear Activation을 사용해서 정보 손실을 방지**하는 선택을 하기도 함

## 5. 이번 강의 핵심 요약

- [x] MLP는 **행렬 곱 + 벡터 더하기 + 활성화 함수**의 반복으로 간결하게 표현 가능 (`y = F(x·W + b)`)
- [x] 이 표현 방식 덕분에 노드 수가 많아져도 수식은 복잡해지지 않음 (shape만 신경 쓰면 됨)
- [x] **Linear Activation만 사용하면, 아무리 층을 깊게 쌓아도 표현력은 1층짜리와 동일함** (여러 개의 W가 곱해져도 결국 하나의 행렬로 합쳐지기 때문)
- [x] 비유: `y=(a1×a2)x+b`(3개 파라미터)와 `y=ax+b`(2개 파라미터)는 완전히 동일한 성능 — 그냥 기울기 하나를 쪼갠 것에 불과
- [x] **비선형(Non-linear) 활성화 함수를 써야만** 층을 깊게 쌓는 것이 실제로 더 복잡한 함수 표현으로 이어짐
- [x] 실질적인 신경망의 "표현력(깊이)"은 **비선형 활성화 함수가 몇 번 등장하는지**로 결정됨
- [x] 그럼에도 Linear Activation을 쓰는 경우: ① **회귀 문제의 마지막 출력층** (-∞~∞ 값을 얻기 위해), ② **병목(bottleneck)처럼 노드 수가 줄어드는 층**에서 정보 손실 방지

## 용어 정리

| 용어 | 의미 |
|---|---|
| 행 벡터 (Row Vector) | 가로로 값이 나열된 벡터 (1×n 형태) |
| shape (크기) | 행렬/벡터가 몇 행 몇 열인지를 나타내는 것 |
| Linear Activation | 입력을 그대로 출력하는 활성화 함수 — 여러 층을 쌓아도 결국 1층으로 합쳐짐 |
| Non-linear Activation (비선형 활성화 함수) | 층을 깊게 쌓을수록 실질적으로 더 복잡한 함수 표현이 가능하게 해주는 활성화 함수 |
| ReLU | 0보다 작은 값은 0으로, 0 이상인 값은 그대로 출력하는 대표적인 비선형 활성화 함수 |
| 병목(Bottleneck) 구조 | 신경망 중간에 노드 수가 확 줄어드는 구간 (정보 손실 위험이 있어 Linear Activation을 쓰기도 함) |
