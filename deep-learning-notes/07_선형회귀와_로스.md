# 7강. 선형회귀 (Linear Regression)와 로스(Loss)

> 딥러닝 강의 7강 정리 노트

---

## 1. 회귀(Regression)란?

> **회귀 = 입력과 출력 간의 관계를 알아내는 것**

- **선형(Linear)**으로 그 관계를 알아내면 → **선형회귀**
- 비선형으로 알아내면 → 그냥 회귀 (비선형 회귀)

### 왜 입력-출력 관계를 알아내려 할까?
- 그래야 **처음 보는 입력**에 대해서도 적절한 출력을 예측할 수 있음
- 예: 조회수와 수익의 관계를 `ax + b` 형태로 알아내서, 새로운 영상의 조회수만 보고도 수익을 예측

### 분류(Classification) vs 회귀(Regression) — 본질은 같다

- 둘 다 "입력 → 적절한 출력을 예측"한다는 본질은 동일
- 차이는 **최종 출력의 형태**뿐
  - 분류: 딱딱 떨어지는 값 (카테고리)
  - 회귀: 연속적인 값 (실수)

---

## 2. 문제 설정: 조회수로 수익 예측하기

- 목표: **최적의 웨이트(a)와 바이어스(b)**를 알아내는 것
- 머신러닝이므로 **데이터 기반**으로 알아냄
- 예시: 유튜브 채널의 영상 5개에서 (조회수, 수익) 데이터를 가져옴
  - 대체로 조회수가 클수록 수익도 큼 (완벽한 직선은 아니지만 경향성 있음)
- 초기의 `a, b` 값은 랜덤하게 설정됨 → 처음엔 예측선이 엉망 (이상한 형태)
- **목표**: 이 초기 랜덤한 `a, b`를 점점 개선해서 **이상적인 직선**을 찾아가는 것

---

## 3. "좋은 a, b"를 어떻게 판단할까? → 로스(Loss)가 필요

- 눈으로 보면 어떤 직선이 더 좋은지 대충 감이 옴 (정성적 판단)
- 하지만 **"얼마나" 좋은지/나쁜지**를 정량적으로 말하려면 **로스(Loss)**가 필요

> **로스 = 얼마나 안 좋은지를 정량적으로 나타내는 지표**
> **로스를 최소로 만드는 a, b = 최적의 a, b**

- 로스는 "내가 풀고 싶은 문제"에 맞게 직접 정의하는 것 (정해진 하나의 공식이 아님)

---

## 4. 로스(Loss) 설계 과정

### 1단계: 에러(Error) 정의

- 실제값(y)과 예측값(ŷ, y-hat)의 차이를 **에러**라고 정의
- 예: 다섯 번째 데이터의 에러 → `e5 = y5 - ŷ5` (실제 - 예측)

### 2단계: 단순히 에러를 다 더하면 안 되는 이유

- 만약 `에러 = 실제 - 예측` 를 그냥 다 더하면:
  - 예측이 실제보다 크거나 작거나 부호가 섞여서 서로 **상쇄**될 수 있음
  - 예: 실제-예측 = +1000, 다른 데이터는 -1000 → 합치면 0이 되어 "완벽하다"고 착각하게 됨
  - 실제로는 전혀 완벽하지 않은데도 로스가 0으로 계산되는 오류 발생

### 3단계: 제곱(또는 절댓값)으로 양수화

- 에러를 **제곱**해서 항상 양수가 되도록 만듦
- (또는 **절댓값**을 취해도 양수화 가능 — 둘 다 실무에서 사용됨)

---

## 5. MSE vs MAE: 제곱을 쓸 때와 절댓값을 쓸 때의 차이

### 그래프로 비교 (바이어스 b=0 고정, 웨이트 a만 변화시키며 관찰)

| 방식 | 에러(e)를 a에 대해 그린 모양 |
|---|---|
| 절댓값 (`\|e\|`) | 뾰족한 **V자(태권브이 모양)** 함수 |
| 제곱 (`e²`) | 부드러운 **이차함수(포물선)** 모양 |

### 핵심 차이: 에러가 커질수록 반응하는 정도

- 에러가 **2배**로 벌어졌을 때:
  - 절댓값 방식: 로스도 그대로 **2배**
  - 제곱 방식: 로스가 **4배**로 커짐 (제곱이라서)

> **제곱(MSE)은 큰 에러(아웃라이어)에 훨씬 더 민감하게 반응함**

### 아웃라이어(이상치)가 있는 경우

- 데이터 대부분은 일정한 패턴을 따르는데, 하나만 크게 벗어난 값(아웃라이어)이 있는 상황
- 제곱을 사용하면(MSE) → 이 아웃라이어 하나 때문에 로스가 급격히 커져서, 전체 회귀선이 그 아웃라이어 쪽으로 크게 끌려감
- 절댓값을 사용하면(MAE) → 아웃라이어에 상대적으로 덜 민감하게 반응함

> **아웃라이어가 있는 상황에서는 MAE가 더 나을 수도 있음**

### 용어 정리

| 이름 | 계산 방법 | 의미 |
|---|---|---|
| **MSE (Mean Squared Error)** | 에러를 제곱해서 다 더함 | 큰 에러(아웃라이어)에 민감 |
| **MAE (Mean Absolute Error)** | 에러의 절댓값을 다 더함 | 아웃라이어에 상대적으로 덜 민감 |

> 둘 다 사용 가능하지만, **차이를 알고 상황에 맞게 선택**해서 써야 함

### 참고: 굳이 "평균(개수로 나누기)"을 안 해도 되는 이유

- 정확한 MSE 정의는 (제곱합) ÷ (데이터 개수)
- 하지만 개수로 나누는 것은 **그래프의 세로 크기(스케일)만 바꿀 뿐, 최솟값의 위치(어떤 a, b에서 최소가 되는지)는 바뀌지 않음**
- 우리의 목표는 "최소가 되는 지점"을 찾는 것이므로, 나누지 않아도 결과에 영향 없음 → 이 강의에서는 간단히 나누지 않고 설명

## 6. 최적의 a, b 찾는 방법: 그리드로 값을 바꿔보며 로스 그리기

### 방법
1. `a`와 `b`를 다양한 값으로 계속 바꿔봄
2. 각 `(a, b)` 조합마다 로스 값(제곱합)을 계산해서 찍음
3. `a`, `b`를 축으로 하고, 로스 값을 `z`축(높이)으로 하는 3차원 그래프를 그림
4. 이 그래프는 **이차함수(포물선) 모양의 곡면**으로 나타남 (제곱의 합이기 때문)
5. 이 곡면에서 **가장 낮은(최소) 지점**의 `(a, b)`가 바로 **최적의 a, b**

### 주의할 점

- 로스 그래프는 항상 **0보다 큼** (제곱의 합이라서 음수가 될 수 없음)
- 데이터 점들이 정확히 일직선 위에 있지 않은 이상, 로스가 정확히 0이 되는 `a, b`는 **존재하지 않음**

---

## 7. 이 방법(그리드 탐색)의 한계

### 문제점: 웨이트/바이어스가 많아지면 불가능해짐

- 지금 예시는 파라미터가 `a, b` **단 2개**라서 그래프로 그려서 최소값을 찾을 수 있었음
- 하지만 실제 신경망은 웨이트와 바이어스 개수가 훨씬 많음 (17개, 18개, 19개...)
  - 파라미터가 3개 이상만 되어도 이런 식으로 일일이 값을 바꿔가며 그래프로 그리는 것은 **사실상 불가능**
- 심지어 **GPT-3**는 파라미터가 **1500억 개**
  - → 이 방식으로는 절대 불가능

### 해결책: 경사법 (Gradient Descent)

- 이런 문제를 해결하기 위한 더 스마트한 방법이 바로 **경사하강법(Gradient Descent)**
- 다음 강의에서 다룰 예정

## 8. 이번 강의 핵심 요약

- [x] **회귀 = 입력과 출력 간의 관계를 알아내는 것** (선형이면 선형회귀)
- [x] 분류와 회귀는 본질적으로 같고, **출력의 형태(이산 vs 연속)만 다름**
- [x] **로스(Loss)** = 예측이 얼마나 안 좋은지를 정량화한 지표
- [x] 에러를 그냥 더하면 부호가 상쇄되는 문제 → **제곱 또는 절댓값**으로 해결
- [x] **MSE**: 아웃라이어에 민감 (제곱이라 큰 에러를 크게 반영)
- [x] **MAE**: 아웃라이어에 상대적으로 둔감
- [x] 최적의 a, b = **로스를 최소화하는 지점**
- [x] 파라미터가 적을 땐 그리드 탐색이 가능하지만, **파라미터가 많아지면(GPT-3처럼) 불가능** → 다음 강의: 경사하강법(Gradient Descent)

## 용어 정리

| 용어 | 의미 |
|---|---|
| 회귀 (Regression) | 입력과 출력 간의 관계를 알아내는 것 |
| 선형회귀 (Linear Regression) | 그 관계를 선형(직선)으로 알아내는 것 |
| 로스 (Loss) | 예측이 실제와 얼마나 다른지를 정량화한 지표 |
| 에러 (Error) | 실제값과 예측값의 차이 |
| MSE (Mean Squared Error) | 에러 제곱의 합(평균) — 아웃라이어에 민감 |
| MAE (Mean Absolute Error) | 에러 절댓값의 합(평균) — 아웃라이어에 상대적으로 덜 민감 |
| 경사하강법 (Gradient Descent) | 파라미터가 많을 때 최적값을 효율적으로 찾는 방법 (다음 강의) |
