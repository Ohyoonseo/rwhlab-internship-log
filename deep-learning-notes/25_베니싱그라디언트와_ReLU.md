# 25강. 베니싱 그라디언트(Vanishing Gradient)와 ReLU

> 딥러닝 강의 25강 정리 노트

---

## 1. 베니싱 그라디언트란?

> **레이어가 많을수록, 입력층에 가까운 층일수록 그라디언트(미분값)가 점점 작아져서 거의 사라지는 문제**

- "베니싱(Vanishing)" = 사라진다는 뜻

### 백프로파게이션 수식에서 원인을 찾을 수 있다

- 이전 강의에서 배운 패턴: **"액웨 액웨 ... 액 나"**
  - 출력층에서 입력층 쪽으로 갈수록(백프로파게이션), 층이 하나씩 늘어날 때마다 **"액웨"가 하나씩 추가됨**
  - "액" = 활성화 함수의 미분값

### 문제의 핵심: 시그모이드의 미분값은 항상 1보다 작다

- 시그모이드 함수의 미분값은 **최댓값이 1**이고, 대부분의 구간에서 1보다 훨씬 작음
- 입력층에 가까운 웨이트의 미분을 구하려면 이 "1보다 작은 값"을 **여러 번 곱해야 함**
  - 예: 층이 3개면 미분값을 3번 곱함 → `0.x × 0.x × 0.x` → 값이 기하급수적으로 작아짐
- 결과: **입력층에 가까운 웨이트일수록 그라디언트가 거의 0에 수렴** → 업데이트가 거의 일어나지 않음

---

## 2. 비유 ①: 줄다리기(진동 전달)

> 미분이란 "웨이트를 살짝 바꿨을 때, 최종 로스가 얼마나 바뀌는지"를 나타내는 값

- 입력층에 가까운 웨이트를 살짝 흔들어봐도, 시그모이드를 여러 번 통과하면서 그 진동이 점점 잦아듦
- 마치 **긴 줄의 앞쪽을 흔들어도, 뒤쪽까지 진동이 거의 전달되지 않는 것**과 같음
- → 앞쪽 웨이트를 아무리 바꿔도 로스가 거의 변하지 않는다 = **그 웨이트에 대한 그라디언트가 거의 0**이라는 뜻

---

## 3. 비유 ②: 회사 조직 (사원-부장-임원)

> 각 레이어를 회사의 직급으로, 노드를 사람으로 비유

```
입력층에 가까운 층 = 사원
중간층 = 부장
출력층에 가까운 층 = 임원
```

- **임원**: 로스(최종 결과)와 가까이 있어서 학습(피드백)이 잘 됨 — 회사가 나아갈 방향을 잘 앎
- **사원**: 그라디언트가 거의 도달하지 못해서 **거의 학습이 안 됨** — 웨이트 초기화 상태(갓 태어난 상태) 그대로 머무름

### 왜 이게 문제인가? — "사원이 망친 재료는 임원도 못 살린다"

- 입력 데이터를 처리하는 **사원(입력층 근처)의 웨이트가 업데이트되지 않으면**, 계속 형편없는 결과물을 다음 층으로 넘김
- 아무리 **부장, 임원(뒷단 레이어)이 학습이 잘 되어 실력이 좋아져도**, 애초에 사원이 망쳐놓은 재료를 가지고는 좋은 결과를 낼 수 없음

### 비유 ③: 중국집 (재료손질 → 요리 → 플레이팅)

```
재료손질 팀(입력층 근처) = 아직 학습 안 된 갓난아기
요리 팀(중간층)
플레이팅 팀(출력층 근처) = 이연복급 실력자
```

- 재료손질 팀(아기)이 재료를 다 망쳐놓음 (춘장 흘리고, 다 태워먹음)
- 아무리 플레이팅 팀이 뛰어나도(그릇 예쁘게 세팅, 고명 완벽하게 올림), **이미 재료 자체가 망가졌기 때문에 맛있는 음식이 나올 수 없음**

> **정리: 앞에서 입력 데이터를 망쳐놓으면, 뒤에서 아무리 손을 써도 소용이 없다**

---

## 4. 그래서 생기는 문제: 언더피팅 (Underfitting)

- 신경망이 이론적으로는 복잡한(꼬불꼬불한) 함수를 표현할 수 있는 능력이 있어도
- 베니싱 그라디언트 때문에 입력층 웨이트가 학습되지 않으면, **데이터에 제대로 다가가지도 못하는 상태**가 됨
- 예: 원래는 조회수-수익 데이터를 `ax+b`만으로도 적당히 맞출 수 있는데, 오히려 복잡한 신경망을 썼다가 베니싱 그라디언트가 발생하면 **아예 데이터 근처에도 못 가는 최악의 결과**가 나옴
- → 이런 현상을 **언더피팅(Underfitting)**이라고 부름

---

## 5. 해결책: 활성화 함수를 ReLU로 바꾸기

### ReLU (Rectified Linear Unit)

```
ReLU(x) = x        (x > 0일 때, 들어온 대로 그대로 나감)
ReLU(x) = 0        (x ≤ 0일 때, 그냥 0을 출력)
```

- 매우 단순한 함수: **양수는 살리고, 음수는 죽인다**

### 왜 베니싱 그라디언트를 해결하는가?

| 구간 | ReLU의 미분값 |
|---|---|
| 양수 구간 | **1** (들어온 대로 그대로 나가므로) |
| 음수 구간 | **0** |

- 시그모이드는 항상 1보다 작은 값을 계속 곱해서 그라디언트가 필연적으로 작아짐
- **ReLU는 양수 구간에서 미분값이 정확히 1** → 여러 층을 거쳐도 곱해지는 값이 1이라서 **그라디언트가 작아지지 않고 그대로 전달됨**
- 다만 음수 구간에서는 미분이 0이 되어 완전히 죽어버리는 리스크는 있음

---

## 6. ReLU의 변형들

### Leaky ReLU

```
양수 구간: 그대로 통과 (동일)
음수 구간: 완전히 0으로 죽이지 않고, 아주 작은 기울기(예: 0.01×x)로 살려둠
```

- "음수를 아예 죽여버리는 건 너무 가혹하지 않냐"는 문제의식에서 등장

### Parametric ReLU (PReLU)

```
음수 구간의 기울기(a)를 고정값으로 정하지 않고, 학습 가능한 파라미터로 둠
```

- 기울기 `a`도 웨이트/바이어스처럼 **그라디언트 디센트로 함께 학습**시킴
- 가능한 이유: `a`에 대한 편미분도 체인룰로 문제없이 구할 수 있기 때문 (백프로파게이션이 정상적으로 작동)
- 새로운 학습 파라미터를 신경망에 추가할 수 있는지 판단하는 기준은 딱 하나: **미분 가능한가?**

---

## 7. 그럼 그냥 Linear Activation을 쓰면 안 되나? (자연스러운 의문)

> "리니어 액티베이션은 미분값이 항상 1이니까, 베니싱 그라디언트가 아예 안 생기지 않나?"

- **맞다. Linear Activation을 쓰면 베니싱 그라디언트는 완벽하게 해결된다**
- **하지만 결정적인 문제가 있음**: Linear Activation만 계속 쓰면 (이전 강의에서 배웠듯) **비선형성(Non-linearity)이 완전히 사라짐**
  - 아무리 층을 깊게 쌓아도 결국 1층짜리 선형 함수로 합쳐져 버림
  - 인공신경망이 복잡한 함수를 표현할 수 있는 능력 자체를 잃어버리게 됨

> **결론: 베니싱 그라디언트를 해결하겠다고 비선형성을 포기할 수는 없다** — ReLU는 "양수 구간은 미분 1을 유지(베니싱 그라디언트 방지)"하면서도 "음수 구간에서 꺾음으로써 비선형성은 확보"하는, 두 마리 토끼를 잡는 절묘한 설계

- 그래서 Linear Activation은 보통 마지막 출력층에서만 사용하고, 중간 층에서는 잘 사용하지 않음 (단, MobileNetV2처럼 정보 손실 방지를 위해 의도적으로 중간에 쓰는 경우도 있음 — 17강 참고)

---

## 8. 중요한 반전: "ReLU를 쓴다고 무조건 베니싱 그라디언트가 해결되는 건 아니다"

### 실험: 노드 수가 하나뿐인 매우 좁은 신경망으로 비교

- 시그모이드 vs ReLU를 비교했을 때, **노드 수가 극단적으로 적으면(예: 1개)** ReLU를 쓴 쪽이 오히려 베니싱 그라디언트가 더 심하게 발생할 수 있음
- 이유: ReLU는 **음수가 들어오는 순간 그 경로(path)가 완전히 0으로 죽어버림**
  - 노드가 하나뿐이라면, 단 한 번이라도 중간에 음수가 나오면 그 뒤로는 완전히 그라디언트가 0
- 반면 시그모이드는 값이 작아지긴 해도 **완전히 0이 되지는 않음** — 계속 아주 작은 값이라도 흘러감

### 노드 수가 충분히 많다면? — 여러 "경로(패스)"가 그라디언트를 구원한다

- 이전 강의(백프로파게이션)에서 배운 원리: **한 웨이트로 가는 경로가 여러 개라면, 그 경로별 미분을 전부 더해줘야 함**
- 노드 수가 많으면, 하나의 웨이트에 도달하는 경로도 여러 개(예: 6개)가 됨
- ReLU를 쓴 경우: 6개 경로 중 일부는 음수를 만나 죽어도(0), **나머지 살아있는 경로들은 정확히 미분값 1을 유지한 채로 그라디언트를 전달**함
- 시그모이드를 쓴 경우: 6개 경로 모두 "약하게라도" 다 곱해지긴 하지만, 각 경로가 전부 1보다 작은 값들의 곱이라 **다 더해봐야 여전히 미미함** ("티끌 모아 티끌")

> **정리: ReLU의 전략은 "확실히 살릴 경로는 완벽하게(미분값 1로) 살리고, 죽일 경로는 확실하게 죽인다"는 방식. 노드 수가 충분히 많아야 살아남는 경로가 확보되어 이 전략이 효과를 발휘한다.**

- 즉, **"ReLU = 무조건 베니싱 그라디언트 해결"이 아니라 "노드 수가 충분할 때 ReLU가 효과적으로 작동한다"**는 조건이 붙음

## 9. 실제 실험 결과로 확인하기

### 실험 설정

- 동일한 모델(11개 층 정도의 컨볼루션 레이어), 동일한 문제(이미지 분류, 예: MNIST/CIFAR-10 계열)
- **활성화 함수만 시그모이드 vs ReLU로 바꿔서 비교**

### 결과

| 활성화 함수 | 그라디언트 크기(입력층 근처) | 최종 테스트 정확도 |
|---|---|---|
| **시그모이드** | 처음부터 끝까지 거의 0 (완전히 죽어있음) | **11%** (거의 랜덤 찍기 수준, 10개 분류 문제에서 10%가 랜덤) |
| **ReLU** | 학습 내내 값이 잘 살아있고 활발하게 움직임 | **90.5%** |

> **활성화 함수 하나만 바꿨을 뿐인데, 학습 자체가 성립하느냐 마느냐 수준의 극적인 차이가 발생함**

### 참고: 옵티마이저(Adam)로 인한 예외적 현상

- 실험 중, 시그모이드를 썼는데도 **첫 번째 층의 웨이트가 업데이트되는 특이 현상**이 관찰됨
- 원인 추정: **Adam(RMSProp 성분)의 분모가 매우 작아지면서, 작은 그라디언트값이 급격히 증폭되어 업데이트 폭이 커진 것**
- 다만 그 업데이트 방향 자체가 유의미하지 않아서, 실제 성능(로스, 정확도)에는 별 도움이 되지 않았음

---

## 10. ReLU 이후 등장한 자매품들

- **ELU, SELU, GELU** 등 다양한 변형이 존재
- 공통적인 지향점: **비선형성을 어느 정도 유지하면서도, 미분값이 죽지 않도록(그라디언트를 잃지 않도록) 설계**
- 각각 수식이 조금씩 다르고, 특정 하이퍼파라미터가 존재하는 경우도 있음

## 11. 이번 강의 핵심 요약

- [x] **베니싱 그라디언트**: 백프로파게이션 시 "액웨 액웨..." 패턴에서, 시그모이드의 미분(항상 1 이하)이 계속 곱해지면서 입력층 근처의 그라디언트가 기하급수적으로 작아지는 문제
- [x] 비유로 이해: 줄다리기(진동이 뒤까지 전달 안 됨), 회사 조직(사원이 학습을 못 하면 임원도 소용없음), 중국집(재료를 망치면 플레이팅도 소용없음)
- [x] 이로 인해 신경망이 데이터에 제대로 다가가지 못하는 **언더피팅** 현상 발생
- [x] **해결책: ReLU** — 양수 구간 미분값이 정확히 1이라 그라디언트가 작아지지 않으면서, 음수 구간을 꺾어 비선형성도 확보
- [x] Linear Activation은 베니싱 그라디언트를 완벽히 해결하지만 **비선형성을 완전히 잃어버리므로 사용할 수 없음**
- [x] **Leaky ReLU, Parametric ReLU** 등은 ReLU의 "음수를 완전히 죽이는" 단점을 보완한 변형
- [x] **중요한 반전**: ReLU가 무조건 베니싱 그라디언트를 해결하는 것은 아니며, **노드 수가 충분히 많아야** 여러 경로(패스) 중 일부가 살아남아 그라디언트를 안정적으로 전달할 수 있음
- [x] 실제 실험에서 시그모이드(정확도 11%, 거의 학습 안 됨) vs ReLU(정확도 90.5%)로 극적인 차이를 확인

## 용어 정리

| 용어 | 의미 |
|---|---|
| 베니싱 그라디언트 (Vanishing Gradient) | 레이어가 깊어질수록 입력층 근처의 그라디언트가 점점 작아져 사라지는 문제 |
| 언더피팅 (Underfitting) | 모델이 데이터의 패턴조차 제대로 학습하지 못하는 상태 |
| ReLU (Rectified Linear Unit) | 양수는 그대로, 음수는 0으로 만드는 활성화 함수 |
| Leaky ReLU | 음수 구간에도 작은 기울기를 남겨두는 ReLU의 변형 |
| Parametric ReLU (PReLU) | 음수 구간의 기울기 자체를 학습 가능한 파라미터로 둔 ReLU의 변형 |
| 경로(패스)의 합 | 하나의 웨이트로 이어지는 여러 경로의 그라디언트를 모두 더해 전체 그라디언트를 구하는 원리 |
