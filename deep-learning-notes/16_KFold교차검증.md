# 16강. K-Fold 교차검증 (K-Fold Cross Validation)

> 딥러닝 강의 16강 정리 노트

---

## 1. 문제 상황: 데이터가 너무 적을 때

### 예시 설정
- 전체 데이터가 120개밖에 없다고 가정
  - 트레이닝 데이터: 100개
  - 테스트 데이터: 20개
- 트레이닝 데이터(100개)가 이미 적은데, 여기서 또 일부를 밸리데이션 데이터로 떼어내면?
  - → 트레이닝에 쓸 데이터가 더욱 부족해지고, **밸리데이션 데이터도 너무 적어서 편향(bias)될 위험**이 큼

### 왜 편향이 문제인가? (예시)

- 강아지/고양이 분류 문제에서, 밸리데이션 데이터로 딱 20개를 떼어냈는데
- **우연히 그 20개가 전부 강아지 사진**이었다고 가정
- → 이 밸리데이션 데이터를 기준으로 하이퍼파라미터(에폭, 모델 등)를 정하면, **강아지에만 편향된 판단 기준**이 되어버림
- 결과적으로 고양이에 대한 특징은 제대로 반영되지 못한, **불균형한 모델**이 만들어질 위험이 있음

---

## 2. 해결책: K-Fold Cross Validation (K겹 교차검증)

### 핵심 아이디어

> **트레이닝 데이터를 여러 조합(fold)으로 나눠서, 여러 번 다르게 검증하고 그 결과를 평균 내자**

### 예시: K=5 (5-Fold)

- 트레이닝 데이터(100개)를 5개의 덩어리(fold)로 나눔 (각 20개씩)
- **매번 다른 덩어리를 밸리데이션 데이터로 사용**하고, 나머지 4개 덩어리를 훈련 데이터로 사용

```
조합 1: [검증 20개] [훈련 80개] → 모델 1 → 밸리데이션 로스 1
조합 2: [훈련 20개][검증 20개][훈련 60개] → 모델 2 → 밸리데이션 로스 2
조합 3: ... → 모델 3 → 밸리데이션 로스 3
조합 4: ... → 모델 4 → 밸리데이션 로스 4
조합 5: [훈련 80개][검증 20개] → 모델 5 → 밸리데이션 로스 5
```

- 이렇게 **5개의 서로 다른 모델**이 만들어지고, 각각의 **밸리데이션 로스**를 구함
- 이 **5개의 밸리데이션 로스를 평균** 내서 → **평균 밸리데이션 로스**를 구함

### 하이퍼파라미터 선택에 활용하기

- 하이퍼파라미터 세트가 여러 개 있다고 가정 (세트1: 러닝레이트 A + 모델 A, 세트2: 러닝레이트 B + 배치사이즈 B + 모델 B, ...)
- **각 하이퍼파라미터 세트마다** 위의 5-Fold 과정을 전부 수행 → 세트별로 "평균 밸리데이션 로스" 하나씩 얻음
- 세트1의 평균 밸리데이션 로스, 세트2의 평균 밸리데이션 로스, 세트3의 평균 밸리데이션 로스... 를 서로 비교
- **평균 밸리데이션 로스가 가장 낮은 하이퍼파라미터 세트**를 최종 선택

> K-Fold를 쓰면, 특정 한 번의 우연한(편향된) 데이터 분할에 의존하지 않고 **더 안정적으로 하이퍼파라미터를 선택**할 수 있음

---

## 3. 하이퍼파라미터를 정한 후: 최종 모델 만들기

### 검증 데이터를 다시 쓰지 않는 이유

- 하이퍼파라미터(모델 구조, 러닝레이트, 에폭 등)는 이미 **K-Fold 과정을 통해 다 정해진 상태**
- 밸리데이션 데이터의 역할(하이퍼파라미터 결정)은 이미 끝났으므로, 이제는 **검증 데이터 없이** 원래 가진 **전체 트레이닝 데이터(100개)**로 다시 학습시켜서 최종 모델을 만듦
  - 데이터가 원래도 적었으니, 이제는 데이터를 아끼지 않고 전부 학습에 활용

### 또 다른 방법: 앙상블(Ensemble)

- K-Fold 과정에서 이미 **5개의 서로 다른 모델**이 만들어졌으므로, 이 모델들을 새로 학습시키는 대신 **그대로 조합(앙상블)**해서 사용하기도 함

---

## 4. 앙상블(Ensemble) 방법들

### 하드 보팅 (Hard Voting, 다수결)

> **가장 단순한 방법: 여러 모델의 "최종 판단"을 다 모아서 다수결로 결정**

- 예: 같은 사진 하나를 5개 모델에 전부 보여줌
  - 모델 1, 2: "강아지"라고 판단
  - 모델 3, 4, 5: "고양이"라고 판단
  - → 다수결에 의해 최종 결론: **"고양이"**

### 소프트 보팅 (Soft Voting)

> **각 모델의 출력(확률값)을 평균 내서 판단**

- 예: 
  - 모델 A: 강아지일 확률 99%
  - 모델 B: 강아지일 확률 51%
  - 모델 C: 강아지일 확률 52%
  - 모델 D: 강아지일 확률 20%
- 단순 다수결(하드 보팅)이라면 강아지 3표, 고양이 1표로 강아지가 이길 수 있지만
- **소프트 보팅**은 확률 자체를 평균 내기 때문에, 강하게 확신하는 모델(99%)의 의견에 더 힘이 실리는 효과가 있음
- 즉, 각 모델이 얼마나 "확신"하는지까지 반영해서 더 정교한 판단이 가능

---

## 5. 참고: K-Fold의 범위

- 강의에서 다룬 "K-Fold Cross Validation" 자체는 **데이터를 여러 조합으로 나눠서 검증하는 방식**을 의미함
- 이걸 "하이퍼파라미터를 선택하는 데 활용하는 것"은 **K-Fold를 응용하는 방법 중 하나**일 뿐, K-Fold 자체의 정의와는 별개의 이야기임
- (일반적인 블로그 등에서 K-Fold를 설명할 때는 보통 "데이터를 나누는 방식"까지만 설명하는 경우가 많음 — 여기에 하이퍼파라미터 선택까지 확장한 것)

---

## 6. 이번 강의 핵심 요약

- [x] 데이터가 적을 때, 밸리데이션 데이터를 한 번만 떼어내면 **우연히 편향된 데이터**가 뽑힐 위험이 있음
- [x] **K-Fold Cross Validation**: 데이터를 K개의 덩어리로 나눠, 매번 다른 덩어리를 검증용으로 사용하며 K번 학습/검증을 반복
- [x] K개의 밸리데이션 로스를 **평균**내서 하이퍼파라미터 세트의 성능을 비교하고, **평균이 가장 낮은 세트**를 선택
- [x] 하이퍼파라미터가 정해지면, **검증 데이터 없이 전체 트레이닝 데이터로 최종 학습**하거나, **K개의 모델을 앙상블**해서 사용
- [x] **하드 보팅**: 각 모델의 최종 판단(카테고리)을 다수결로 결정
- [x] **소프트 보팅**: 각 모델의 확률(출력값) 자체를 평균 내서 판단 — 확신이 강한 모델의 의견이 더 반영됨

## 용어 정리

| 용어 | 의미 |
|---|---|
| K-Fold Cross Validation | 데이터를 K개로 나눠, 매번 다른 부분을 검증용으로 삼아 K번 검증하는 방법 |
| Fold | K-Fold에서 나눠진 데이터 덩어리 하나 |
| 앙상블 (Ensemble) | 여러 개의 모델을 조합해서 최종 판단을 내리는 방법 |
| 하드 보팅 (Hard Voting) | 여러 모델의 최종 분류 결과를 다수결로 결정하는 앙상블 방식 |
| 소프트 보팅 (Soft Voting) | 여러 모델의 확률(출력값) 자체를 평균 내서 결정하는 앙상블 방식 |
