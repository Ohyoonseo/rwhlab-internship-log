# Part 0. 한눈에 보기

## 0-1. 세 줄 요약

1. **문제:** 로봇 정책은 처음 보는 물체·명령에 약해. 인터넷으로 학습한 비전-언어 모델(VLM)을 가져다 로봇 동작을 출력하게 만든 **VLA**가 해답으로 떠올랐는데, 기존 VLA(RT-2-X 등)는 **비공개**이고 **새 로봇에 맞추는(파인튜닝) 방법**이 연구되지 않았어.
2. **해결:** 70억 파라미터짜리 **오픈소스 VLA, OpenVLA**를 만들었어. 핵심 트릭은 로봇 동작을 **256칸짜리 "단어(토큰)"로 바꿔서** 언어 모델이 문장 쓰듯 동작을 쓰게 한 것.
3. **결과:** 7배 큰 RT-2-X보다 좋거나 비슷하고, 새 로봇에 파인튜닝해도 평균 1등. **LoRA**로 GPU 1대 학습, **4비트 양자화**로 7GB 메모리 실행까지 가능.

## 0-2. 논문 흐름 지도

```
[1장 서론]        왜 필요해?    → 로봇 일반화 문제 + 기존 VLA의 2가지 한계
      ↓
[2장 관련 연구]    남들은?      → VLM / 범용 로봇 정책(Octo) / VLA(RT-2-X)와의 차이
      ↓
[3장 모델]        어떻게?      → 구조, 행동 토큰화(핵심!), 데이터, 설계 결정, 인프라
      ↓
[4장 코드]        뭘 공개?     → 학습/파인튜닝/추론 코드
      ↓
[5장 실험]        잘 돼?       → Q1 바로 써보기 / Q2 파인튜닝 / Q3 효율화
      ↓
[6장 한계]        뭐가 부족?   → 입력 1장, 느림, 신뢰도, 미해결 질문
```

## 0-3. Abstract의 "문제 2개"가 논문 전체를 관통해

| 문제 (1장) | 해결 (어디서?) |
|---|---|
| ① 기존 VLA는 **비공개** | 모델·코드·데이터 구성 전부 공개 (4장) |
| ② **파인튜닝** 방법 연구가 없음 + 일반 하드웨어에서 못 씀 | 파인튜닝 실험 (5.2), LoRA (5.3), 양자화 (5.4) |

## 0-4. OpenVLA의 일생 — 각 기술이 어디서 쓰이나 ⭐

```
[부품 사전학습]  SigLIP, DINOv2, Llama 2      ← 구글·메타가 각자 (수조 개 데이터)
       ↓
[조립·정렬]     Prismatic VLM                ← Karamcheti 팀 (사진-글 약 100만)
       ↓
[1차 파인튜닝]  VLM → OpenVLA 만들기          ← 이 논문 (OpenX 97만, A100 64대 × 14일)
               = "로봇 사전학습"                 전체 파라미터 학습, LoRA ❌ 양자화 ❌
       ↓ 공개
[2차 파인튜닝]  내 로봇에 맞추기               ← 사용자 (시범 10~150개)
                                              ✅ LoRA 여기! (GPU 8대 → 1대)
       ↓
[추론·실행]     로봇 실제로 움직이기            ← 사용자
                                              ✅ 양자화 여기! (16.8GB → 7.0GB)
```

# Part 1. 기초 개념

## 1-1. 정책 (Policy)

**정책 = "지금 보이는 상황 → 어떤 행동을 할지" 정하는 함수.** 로봇의 두뇌.

```
π(관찰) = 행동
```

## 1-2. 사전학습 → 파인튜닝

| 단계 | 비유 | 데이터 |
|---|---|---|
| **사전학습** | 초중고에서 기초를 넓게 배우기 | 엄청 많음 |
| **파인튜닝** | 대학에서 전공 배우기 | 상대적으로 적음 |
| **처음부터 (from scratch)** | 기초 없이 바로 전공 | 파라미터를 랜덤으로 시작 |

## 1-3. ⭐ "파인튜닝"이 두 번 있어 (제일 헷갈리는 부분)

| | 1차 | 2차 |
|---|---|---|
| 하는 일 | VLM → VLA **만들기** | VLA → 특정 로봇에 **적응시키기** |
| 출발점 | Prismatic VLM | 완성된 OpenVLA |
| 데이터 | OpenX 로봇 궤적 97만 개 | 새 로봇 시범 10~150개 |
| 논문 속 이름 | VLM 입장: "파인튜닝"<br>로봇 입장: **"OpenX 사전학습", "로봇 사전학습"** | "새 환경에 파인튜닝" |
| RT-2-X | ✅ 함 | ❌ 안 함 (비공개라 불가능) |
| OpenVLA | ✅ | ✅ (5.2, 5.3절) |

> 💡 같은 단계를 관점에 따라 다르게 불러. 2차 기준으로 보면 1차는 "미리 해둔 학습"이라 **로봇 사전학습**이라고 부름.
> "RT-2-X는 파인튜닝 상황을 안 다뤘다" = **2차**를 안 했다는 뜻.

## 1-4. VLM vs VLA

| | VLM | VLA |
|---|---|---|
| 풀네임 | Visually-conditioned Language Model | Vision-Language-Action model |
| 입력 | 사진 + 글 | 사진 + 글(명령) |
| 출력 | **글** | **로봇 동작** |
| 예 | Prismatic, LLaVA, PaLI | OpenVLA, RT-2-X |

**VLA = VLM을 파인튜닝해서 출력을 글 대신 로봇 동작으로 바꾼 것.** (자세한 과정 → Part 3)

## 1-5. 토큰 · 어휘집 · 임베딩 · 패치

| 개념 | 뜻 | 예시 |
|---|---|---|
| **토큰** | 글을 쪼갠 조각 | "eggplant" → [" egg", "plant"] |
| **어휘집** | 모델이 아는 토큰 전체 목록 | Llama 2는 **32,000개** |
| **임베딩** | 토큰 ID를 긴 숫자 벡터로 바꾼 것 | 토큰 하나 = **4096차원** |
| **패치** | 사진을 쪼갠 정사각형 조각 | 224×224 ÷ 14×14 → **16×16 = 256개** |

**patch-as-token:** 이미지 패치를 단어처럼 문장 앞에 끼워 넣는 방식 (요즘 VLM 표준)
```
[패치1][패치2]...[패치256] [What][should][the][robot][do]...
 └── 이미지에서 온 "가짜 단어들" ──┘ └──── 진짜 단어들 ────┘
```

## 1-6. 7차원 행동

| Δx, Δy, Δz | Δroll, Δpitch, Δyaw | grip |
|---|---|---|
| 손끝 이동량 (3) | 손목 회전량 (3) | 그리퍼 열기/닫기 (1) |

- Δ = "지금 위치에서 얼마나 더" → **상대 제어**
- 손끝(엔드이펙터)을 명령하고, 관절을 얼마나 돌릴지는 로봇 내부 **역기구학**이 계산
- ⚠️ "7차원 행동"과 Franka 로봇의 "7자유도(관절 7개)"는 **우연히 숫자만 같은 다른 개념**

# Part 2. 모델 해부

## 2-1. 부품 → 완성품 → 개조 (Prismatic과의 관계)

컴퓨터 조립에 비유하면:

```
[1단계] 부품 (각 회사가 따로, 서로 모르는 사이)
   SigLIP  (구글) ─ 사진+글로 학습 → "이게 뭐냐" (의미)
   DINOv2  (메타) ─ 사진만으로 학습 → "어디에 어떤 모양으로" (공간)
   Llama 2 (메타) ─ 글만으로 학습  → 언어, 상식
        ↓
[2단계] 조립 + 연결 학습 → Prismatic-7B VLM (Karamcheti 팀)
   ① 조립: 눈 두 개 출력을 이어붙이고 + MLP 프로젝터(유일하게 새로 만든 부품) + Llama 2
   ② 정렬(alignment): 사진-글 약 100만 개(LLaVA 1.5)로 학습
      → 눈이 본 "보라색 길쭉한 것"과 두뇌의 단어 "가지"가 연결됨
   → "사진 보고 글로 답하는 모델"
        ↓
[3단계] 개조 → OpenVLA (이 논문)
   Prismatic 통째로 + OpenX 로봇 데이터 97만 개로 1차 파인튜닝
   → "사진 보고 로봇 동작으로 답하는 모델"
```

| 단계 | 누가 | 데이터 양 |
|---|---|---|
| 부품 사전학습 | 구글, 메타 | **수조 개** 토큰 (대학 연구실은 불가능) |
| Prismatic 조립 | Karamcheti 팀 | 약 100만 개 사진-글 |
| OpenVLA | 이 논문 | 약 97만 개 로봇 궤적 |

> 💡 **Prismatic은 "모델 가족"**: 여러 눈·두뇌 조합을 실험한 논문. OpenVLA는 그중 **DINOv2 + SigLIP + Llama 2 7B, 224px** 조합을 씀.
> 💡 Karamcheti는 Prismatic의 1저자이자 OpenVLA의 공동 1저자 → 자기 팀 완성품을 출발점으로 씀.
> 💡 Prismatic(VLM) 학습 땐 눈을 **얼렸지만**, OpenVLA(VLA) 학습 땐 눈도 **같이 학습**시킴 (→ 4-4).

## 2-2. 각 부품의 역할: 눈 · 통역사 · 두뇌

```
📷 사진 → [DINOv2 + SigLIP] → [MLP 프로젝터] → [Llama 2] → 행동 토큰 7개
              눈                  통역사           두뇌
```

### 👁️ 눈: DINOv2 + SigLIP

| | SigLIP | DINOv2 |
|---|---|---|
| 학습 데이터 | 이미지 + 텍스트 짝 | 이미지만 |
| 잘하는 것 | **의미** ("이건 가지") | **공간** ("꼭지가 왼쪽 아래, 30도") |
| 약한 점 | 설명 글은 정밀한 위치를 말하지 않으니까 위치에 약함 | 이름(의미)은 모름 |
| 출력 (패치당) | 1152차원 | 1024차원 |

로봇은 **"뭔지" + "정확히 어디/어떤 각도"**를 둘 다 알아야 집을 수 있어서 둘을 합침.
**채널 방향 연결:** 패치 수(256)는 그대로 두고, 같은 위치 패치끼리 벡터를 옆으로 이어붙임 → 패치당 2176차원.

### 🗣️ 통역사: MLP 프로젝터

| 항목 | 내용 |
|---|---|
| 하는 일 | ① 크기 맞추기 (2176 → 4096)<br>② 의미 맞추기 (Llama가 단어처럼 이해하는 위치로 옮기기) |
| 구조 | `y = W₂ · GELU(W₁ · x + b₁) + b₂` (2층, 중간에 비선형) |
| 크기 | 약 2600만 개 (전체의 약 0.3%, 중간 차원 4096 가정) |
| 특징 | 256개 패치에 **각각 따로** 적용 → 패치끼리 관계는 **모름** |
| 출신 | Prismatic 때 **처음부터** 만듦, OpenVLA 때 다시 다듬어짐 |

### 🧠 두뇌: Llama 2 7B

| 항목 | 내용 |
|---|---|
| 크기 | 트랜스포머 32층, 약 67억 개 (OpenVLA 전체의 약 90%) |
| ① 정보 섞기 | **어텐션**으로 모든 토큰이 서로를 참조 |
| ② 추론 | 32층을 거치며 이해가 쌓이고, 인터넷 상식(해골, 테일러 스위프트 등) 활용 |
| ③ 행동 쓰기 | 출력층이 32,000개 토큰 확률 계산 → 행동 토큰 7개를 **순서대로** 생성 |

어텐션이 만드는 세 종류의 연결:

| 연결 | 예시 | 필요한 능력 |
|---|---|---|
| 이미지 ↔ 이미지 | 가지 패치가 그릇 패치를 봄 | 공간 관계 |
| 글 ↔ 이미지 | "eggplant" 토큰이 보라색 패치를 찾음 | **언어 그라운딩** |
| 글 ↔ 글 | "put" + "in bowl" | 명령 이해 |

### 통역사 vs 두뇌

| | MLP 프로젝터 | Llama 2 |
|---|---|---|
| 비유 | 통역사 | 두뇌 |
| 크기 | 약 0.3% | 약 90% |
| 패치끼리 관계 | ❌ | ✅ |
| 인터넷 지식 | 거의 없음 | ✅ 대부분 여기 |

> 💡 **왜 통역사가 이렇게 작아도 돼?** 두뇌가 강력하니까 "단어처럼 보이게만" 바꿔주면 나머지는 두뇌가 해. 연결부는 최소한으로, 일은 두뇌에게 → patch-as-token 철학.

## 2-3. 차원 흐름 (Figure 2)

```
사진 224×224
 ├─→ DINOv2 → [256 × 1024]
 └─→ SigLIP → [256 × 1152]
        ↓ 채널 방향 연결
     [256 × 2176]
        ↓ MLP 프로젝터 (패치마다 2176 → 4096)
     [256 × 4096]   ← "이미지 단어 256개"
        +
     "What should the robot do to {명령}? A:"   ← 명령문을 질문 템플릿에 끼움
        ↓
     Llama 2 7B → 행동 토큰 7개 → Action De-Tokenizer → 7차원 행동
```

# Part 3. VLM → VLA 변신 과정 ⭐⭐⭐

## 3-1. 직관: "새 언어로 답하는 연습"

그림 보고 영어로 설명을 잘하는 학생에게, 이제부터 답을 **모스부호로 쓰라고** 하고 정답 예시 97만 개로 연습시키는 것. 그림 이해 능력은 그대로 쓰고, **답을 표현하는 방식만** 새로 배움.

```
VLM 문제: [사진: 고양이] "What is in the image? A:"                          → "A cat on a sofa"
VLA 문제: [사진: 싱크대] "What should the robot do to put eggplant in bowl? A:" → [161][120][179][140][128][125][255]
```
**형식이 완전히 같아!** 바뀐 건 **정답의 내용**뿐 → VLM 학습 코드를 거의 그대로 재활용.

## 3-2. 행동 토큰화: 연속값 → 256칸 단어

**문제:** 언어 모델은 32,000개 중 하나를 고르는 **객관식**만 풀 수 있는데, 로봇 동작은 **연속적인 숫자**(0.0053m).

| 단계 | 내용 |
|---|---|
| ① 차원별 분리 | 7차원 행동을 **차원마다 따로** 처리 |
| ② 범위 정하기 | 학습 데이터의 **1%~99% 분위수** 사이 (차원마다 따로) |
| ③ 256칸 나누기 | 각 값 → 0~255 정수 |
| ④ 토큰 대응 | Llama 어휘집의 **마지막 256개(가장 안 쓰는 토큰)를 덮어씀** |

### 계산 예시
```
Δx의 1% 분위수 = −0.02 m, 99% 분위수 = +0.02 m 라면

칸 폭 = 0.04 / 256 = 0.00015625 m ≈ 0.16 mm

Δx = 0.0053 m 는?
  floor( (0.0053 + 0.02) / 0.00015625 ) = floor(161.92) = 161번 칸

되돌리기 (칸 가운데 값)
  −0.02 + (161 + 0.5) × 0.00015625 ≈ 0.00523 m   (오차 약 0.07 mm)

범위 밖 값 → 맨 끝 칸(0 또는 255)으로 붙임
```

### ① 왜 차원별로 따로?

| | 7개 묶어서 | **차원별로** |
|---|---|---|
| 필요한 토큰 수 | 256⁷ = 2⁵⁶ ≈ 7.2 × 10¹⁶ (7경 개) | **256개** |
| 행동당 토큰 | 1개 | 7개 |
| 학습 가능? | ❌ (데이터로 다 볼 수 없음) | ✅ |

- **차원마다 눈금자가 다름**: 단위(m vs rad)와 범위가 달라서 분위수를 따로 구함
- **토큰 256개는 공유**, **몇 번째 자리냐**로 어느 차원인지 구분 (답안지 칸 위치처럼)
  ```
  [1번째][2번째][3번째][4번째][5번째][6번째][7번째]
    Δx     Δy     Δz   Δroll  Δpitch  Δyaw   grip
  ```
- **칸 나누기는 따로, 생성은 순서대로 앞을 보면서** → 차원 간 관계(들어올릴 땐 그리퍼 닫기)도 반영

### ② 왜 분위수? (RT-2와의 차이)

이상치 Δx = 0.5m가 하나 섞여 있다면:

| | 최솟값-최댓값 (RT-2) | **1~99% 분위수 (OpenVLA)** |
|---|---|---|
| 범위 | −0.02 ~ 0.5 | −0.02 ~ 0.02 |
| 칸 폭 | 0.52/256 ≈ **2 mm** | **0.16 mm** |
| 정상 데이터가 쓰는 칸 | 0.04/0.52 × 256 ≈ **20칸** | **256칸 전부** |

### ④ 왜 덮어쓰기?
- Llama의 빈 특수 토큰 자리는 **100개뿐** (256개 필요)
- 새로 추가하면 임베딩 표·출력층 크기를 바꿔야 함
- → 거의 안 쓰는 마지막 256개 재활용 = **모델 구조 변경 0**

## 3-3. 학습 데이터 준비

```
Step 0. 궤적을 순간별로 쪼개기
  궤적 1개 (50스텝) → 문제 약 50개 (각 순간이 독립 문제, 명령문은 공통)
  첫 순간의 0행동 [0,...,0]은 제거 (→ 6-1 부록 C)

Step 1. 행동 → 칸 번호 → 토큰 ID

Step 2. 템플릿에 끼워 한 줄로
  [이미지 토큰 256개] [What]...[A][:] [a₁][a₂][a₃][a₄][a₅][a₆][a₇]
  └──────────── 입력 (채점 안 함) ────┘ └──── 정답 (채점함) ─────┘
```

## 3-4. 학습 한 스텝 따라가기

### ① 순전파: 예측 만들기
- 사진 → 눈 → 통역사 → 이미지 토큰 256개 / 글 → 임베딩
- 이어붙여서 Llama 32층 통과 → 위치마다 다음 토큰 32,000개 확률
- **teacher forcing:** 정답 a₁~a₆도 입력에 넣어서, 순전파 **한 번에** 7개 예측을 동시에 얻음 (각 위치는 자기보다 앞만 볼 수 있어서 정답을 훔쳐보진 못함)

| 위치 (본 것) | 예측할 것 |
|---|---|
| ... "A:" | a₁ (Δx) |
| ... "A:" + a₁ | a₂ (Δy) |
| ... | ... |
| ... "A:" + a₁~a₆ | a₇ (grip) |

### ② 손실: 정답 7개만 채점
```
L = −ln P(a₁) − ln P(a₂) − ... − ln P(a₇)

정답 확률 0.9  → 0.105 (거의 맞힘)
정답 확률 0.5  → 0.693
정답 확률 0.1  → 2.303 (거의 틀림)
```

### ③ 역전파: 기울기를 출력 → 입력 방향으로
```
손실 → 출력층 → Llama 32층 → 프로젝터 → 시각 인코더 (얼리지 않으니까 눈까지!)
```

### ④ 업데이트
```
θ_새 = θ_옛 − 0.00002 × (배치 2048개의 평균 기울기)
```
70억 개 전부 **아주 조금씩**. 이걸 **27 에폭** 반복 (A100 64대 × 14일).

## 3-5. 학습하면서 모델 안에서 일어나는 일

| 시점 | 상태 |
|---|---|
| **처음** | "A:" 뒤에 영어 단어를 쓰려 함. 행동 토큰(희귀 토큰) 확률 ≈ 0<br>대충 1/32000만 쳐도 손실 ≈ ln(32000) ≈ **10.4** (토큰당) |
| **중간** | **출력층**: "A:" 뒤엔 행동 토큰에 확률을 몰아줌<br>**행동 토큰 임베딩**: 희귀 문자 조각 → "Δx 161번 칸" 같은 새 의미<br>**트랜스포머**: "가지가 왼쪽 아래" 표현 → "손을 왼쪽 아래로" 연결<br>**시각 인코더**: "가지가 있다" → "꼭지가 정확히 여기, 이 각도" |
| **끝** | 행동 토큰 정확도 **95%+**, 손실 ≈ −ln(0.9) ≈ **0.105** (약 1/100) |

## 3-6. 뭐가 그대로고 뭐가 바뀌어?

| 항목 | VLM (Prismatic) | VLA (OpenVLA) |
|---|---|---|
| 모델 구조 | 그대로 | **그대로** |
| 어휘집 크기 | 32,000 | **32,000 그대로** |
| 어휘집 내용 | 일반 토큰 | **마지막 256개만 의미 변경** |
| 입력 형식 | 사진 + 질문 | 사진 + 로봇 질문 템플릿 |
| 출력 | 영어 문장 | **행동 토큰 7개** |
| 학습 목표 | 다음 토큰 예측 + 교차 엔트로피 | **같음** (행동 토큰만 채점) |
| 가중치 | VLM 학습 결과 | **전부 조금씩 변경** (눈 포함) |
| 데이터 | 사진-글 약 100만 | 로봇 궤적 97만 (순간 단위) |

## 3-7. 왜 인터넷 지식이 로봇으로 넘어가?

VLM은 이미 내부에 "이건 해골이다", "컵은 접시 왼쪽" 같은 표현을 만들어. 파인튜닝은 그걸 버리는 게 아니라 **그 위에 "그럼 손을 어디로" 연결선만 새로 까는 것**. 학습률이 작아서(2e-5) 원래 지식은 대부분 남음 → 로봇 데이터에 해골이 없어도 "해골을 건조대에" 가능.

⚠️ 단, 로봇 데이터로만 27바퀴 돌면 **조금씩 까먹을** 수 있음 → RT-2-X의 **co-fine-tuning**(인터넷 데이터를 섞어 학습)이 의미 일반화에서 약간 더 잘한 이유 (→ 4-6, 6장 미해결 질문).

## 3-8. 추론: 학습이 끝난 뒤 로봇 움직이기

```
1. 카메라 사진 + 명령 입력
2. 토큰 7개를 하나씩 생성        → [161, 128, 90, 130, 127, 125, 255]
3. De-Tokenizer: 칸 가운데 값    → [0.00523, ..., 그리퍼 닫기]
4. 로봇이 그만큼 움직임
5. 새 사진 → 1번으로 (폐루프, closed-loop)
```
폐루프라서 **실수에서 회복**(떨어뜨리면 다시 집기)도 가능.

### 5.3 LoRA (Q3 — 학습 비용)

> ⚠️ 각주 4: 5.3, 5.4는 **SigLIP만 쓰는 작은 버전** (Octo와 같은 데이터 구성)

**어디를 학습하나 (🔥 학습 / 🧊 고정)**

| 부분 | Full FT | Last layer | Frozen vision | Sandwich | LoRA |
|---|---|---|---|---|---|
| 시각 인코더 | 🔥 | 🧊 | 🧊 | 🔥 | 🧊 + 덧붙임 🔥 |
| 토큰 임베딩 | 🔥 | 🔥 | 🔥 | 🔥 | 🧊 |
| 트랜스포머 1~31층 | 🔥 | 🧊 | 🔥 | 🧊 | 🧊 + 덧붙임 🔥 |
| 마지막 층 | 🔥 | 🔥 | 🔥 | 🔥 | 🧊 + 덧붙임 🔥 |

**LoRA 원리**
```
y = W·x + B·A·x
W: 고정 🧊 / B (4096×r), A (r×4096): 학습 🔥 (B는 0으로 시작 → 처음엔 원래 모델과 동일)

4096×4096 행렬 하나: 전체 16,777,216개 vs LoRA r=32: 32×8192 = 262,144개 (약 1.56%)
가정: 필요한 변화 ΔW는 저랭크(적은 방향)로 충분
```

**결과 (33 롤아웃)**

| 방법 | 성공률 | 학습 파라미터 | 메모리 (배치 16) |
|---|---|---|---|
| Full FT | 69.7 ± 7.2% | 7,188.1M | 163.3 GB (GPU 2대) |
| Last layer only | 30.3 ± 6.1% | 465.1M | 51.4 GB |
| Frozen vision | 47.0 ± 6.9% | 6,760.4M (**94%**) | 156.2 GB (GPU 2대) |
| Sandwich | 62.1 ± 7.9% | 914.2M | 64.0 GB |
| **LoRA r=32** | **68.2 ± 7.5%** | **97.6M (1.4%)** | **59.7 GB** |
| LoRA r=64 | 68.2 ± 7.8% | 195.2M | 60.5 GB |

**숫자 검산**
```
1.4%        : 97.6 / 7188.1 = 0.01358 ✓
시각 인코더 : 7188.1 − 6760.4 = 427.7M (SigLIP 약 4억) ✓

LoRA r=32
  Llama 층 하나: Q,K,V,O 32768r + gate,up 30208r + down 15104r = 78080r
  × 32층 × 32 ≈ 80.0M
  SigLIP: 20128r × 27층 × 32 ≈ 17.4M
  합계 ≈ 97.4M ≈ 97.6M ✓   (r=64 → 정확히 2배 195.2M ✓)

Last layer only (내 계산): 마지막 층 202.4M + 임베딩 131.1M + 출력층 131.1M ≈ 464.6M ✓
```

**교훈**
- **"몇 개를"보다 "어디를"**: Frozen vision은 94% 학습해도 47.0%, LoRA는 1.4%로 68.2%
- 눈을 새 장면에 적응시키는 게 결정적
- r=32 = r=64 → **r=32 추천**
- GPU **8대 → 1대**
- 메모리가 37%나 남는 이유: **가중치(고정 포함)·활성값**은 그대로, 줄어드는 건 기울기·옵티마이저 상태뿐

### 5.4 양자화 (Q3 — 실행 비용)

**원리 (4비트 예시)**
```
가중치 [0.12, −0.30, 0.05, 0.21]
스케일 s = 0.30 / 7 ≈ 0.04286
저장   q = round(w/s) = [3, −7, 1, 5]   ← 4비트 정수
복원   w ≈ q×s = [0.1286, −0.30, 0.0429, 0.2143]
→ 행동 이산화와 같은 원리를 "가중치"에 적용
```

**결과 (Bridge 8작업, 80 롤아웃)**

| 정밀도 | 성공률 | 메모리 | 속도 (A5000) |
|---|---|---|---|
| bfloat16 | 71.3 ± 4.8% | 16.8 GB | - |
| int8 | **58.1 ± 5.1%** ↓ | 10.2 GB | **1.2 Hz** |
| **int4** | **71.9 ± 4.7%** | **7.0 GB** | 3 Hz |

**미스터리: 왜 8비트가 4비트보다 나빠?**
1. **LLM 추론은 메모리 읽기가 병목(memory-bound)**
   ```
   토큰 1개 = 가중치 전체 읽기
   RTX 4090 (약 1000 GB/s): 15GB → 약 0.015초
   행동 1개 = 토큰 7개 → 약 0.105초 → 최대 약 9.5Hz (실제 약 6Hz)
   ```
   4비트는 읽을 양이 약 1/4 → 오버헤드 감수해도 이득
2. **8비트는 추가 연산(오버헤드)이 무거워서 느림**
3. **느리면 시스템 동역학이 바뀜:** 학습 데이터는 0.2초(5Hz)마다 새 명령, 1.2Hz면 0.83초마다 → 학습 때와 다른 흐름

**증명: "부정확해서"가 아니라 "느려서"**

| 정밀도 | 논블로킹 | **블로킹 (부록 D.4)** |
|---|---|---|
| bfloat16 | 71.3% | 70.0 ± 5.1% |
| int8 | 58.1% | **74.4 ± 4.9%** |
| int4 | 71.9% | 68.8 ± 5.2% |

오프라인 토큰 정확도도 셋 다 비슷 → **원인을 없애서 결과가 사라지는지 확인**한 좋은 실험

## 5-4. Octo-OpenVLA 차이가 Octo-RT-2-X에서도 나타나?

| **Google OOD** | **14.3** | **82.9** | **82.9** | 두 VLA가 **완전히 같고** Octo만 낮음 |

→ RT-2-X가 "Octo vs OpenVLA 차이의 원인은 VLA 방식 자체"라는 **두 번째 증거**

| 차이 종류 | Octo vs OpenVLA | Octo vs RT-2-X |
|---|---|---|
| 사전학습 두뇌 → 일반화 | ✅ | ✅ **똑같이** |

| 유연성·가벼움 | Octo 우세 | Octo 우세 (크기 차이 약 600배로 더 극단) |

⚠️ Bridge에서 OpenVLA가 RT-2-X보다 훨씬 좋은 범주(Visual, Physical)는 Octo와 무관한 **VLA끼리의 차이** (0행동 정리, 데이터 양, 눈 두 개).

## 7-4. 읽을 때 주의할 포인트 🧐

1. **"attribute to", "hypothesize"는 추정.** 확인은 부록 D 절제 실험에서.
2. **"comparable"은 표준오차 구간이 겹친다는 뜻.** (Google 85.0 vs 78.3)
3. **"모든 작업 50% 이상"은 분포 내 + OOD 합산 기준.** 쪼개면 "당근 → 그릇 (OOD)"는 40%.

# Part 8. 내가 했던 질문 Q&A

### Q1. 여러 사전학습 부품들이 Prismatic이랑 무슨 관계야?
**부품(SigLIP, DINOv2, Llama 2)을 조립 + 정렬한 완성품이 Prismatic이고, 그걸 로봇용으로 개조한 게 OpenVLA.** 앞 단계 지식이 다음 단계로 물려 내려감. → Part 2-1

### Q2. RT-2-X도 파인튜닝한 VLA 아니야? 왜 "파인튜닝 상황을 안 다뤘다"고 해?
**파인튜닝이 두 번 있어서 그래.** RT-2-X는 1차(VLM → VLA)는 했지만 2차(완성된 VLA → 새 로봇)는 안 했고, 비공개라 할 수도 없음. → Part 1-3

### Q3. 차원별 분리가 뭐야?
**7개 숫자를 각각 따로 256칸에 넣는 것.** 묶으면 7경 개 토큰이 필요하지만 따로 하면 256개면 됨. 토큰은 공유하고 자리 순서로 구분, 생성은 순서대로라 차원 간 관계도 반영. → Part 3-2

### Q4. 각주 2의 "서로 다른 센서 입력 데이터셋"이 OpenX 데이터야? Octo가 정확히 뭐야?
**맞아, OpenX의 70여 개 데이터셋은 센서가 제각각.** Octo는 그걸 다 토큰으로 바꿔 받아들이는 유연한 오픈소스 범용 정책. → Part 4-3, 5-1

### Q5. Octo가 지금(3.3절) 왜 나와?
**Octo는 역할이 3개(경쟁자 / 레시피 출처 / 대조군).** 3.3절에선 데이터 혼합 비율을 빌려온 **레시피 출처**, 각주 2에선 **대조군**. → Part 5-2

### Q6. OpenVLA는 왜 여러 카메라·고유수용감각·관찰 기록이 다 ❌야?
**일부러 단순하게 만들어서.** ① OpenX 공통분모는 3인칭 사진 1장뿐 ② Prismatic이 사진 1장에 익숙 ③ 이미지 토큰이 늘면 계산량이 제곱으로 늘어 더 느려짐. 6장 한계 1번으로 미룸. → Part 4-3, 4-7

### Q7. Octo-OpenVLA 차이가 Octo-RT-2-X에서는 어떻게 나타나?
**사전학습 두뇌 차이는 똑같이 나타남** (Google OOD: 14.3 vs 82.9 vs 82.9). 파인튜닝 비교는 RT-2-X가 비공개라 불가능. → Part 5-4

### Q8. VLM을 파인튜닝해서 VLA가 된다는 게 뭔 과정이야?
**같은 형식(사진 + 질문 → 답)에서 정답만 행동 토큰으로 바꿔 계속 연습시키는 것.** 구조·손실·코드는 그대로, 데이터·가중치·토큰 256개의 의미만 바뀜. → Part 3 전체

### Q9. MLP 프로젝터와 Llama의 역할은?
**프로젝터 = 통역사** (패치별로 2176 → 4096, 의미 위치 맞추기, 0.3%). **Llama = 두뇌** (어텐션으로 관계 파악, 상식 추론, 행동 토큰 생성, 약 90%). → Part 2-2

### Q10. LoRA, 양자화는 어디서 쓰여?
**둘 다 OpenVLA를 "만들 때"가 아니라 "가져다 쓸 때".** LoRA = 2차 파인튜닝(학습), 양자화 = 추론(로봇 실행). 1차(64대 × 14일)엔 안 씀. QLoRA는 둘을 합친 방법. → Part 0-4
